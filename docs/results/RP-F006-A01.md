# RP-F006-A01 — A finite obstruction to exact prediction from incomplete queue state

**Original, preregistered decision: `FINITE_NONIDENTIFIABILITY_VERIFIED`.**

This is a **synthetic, deterministic, model-conditional witness**.
It neither revises the failed external forecasts RP-E010-P01 or
RP-E011-P01, nor estimates their causal mechanism. It introduces
no physical law and claims no novelty over classical queuing theory.

## Why this mathematical question was selected

Two separate *observational* chronological external studies failed
their registered incremental forecasting benchmarks:

- RP-E010-P01: the aggregate backlog-trend heuristic lost to
  static and historical controls on 49,995 HPC2N heldout tasks.
- RP-E011-P01: with real extended queue labels and 169,189 heldout
  CERIT-SC tasks, the queue-specific trend's MAE was **45,328.01 s**,
  worse than static per-queue/rate **43,953.98 s** and a classical
  historical queue/resource median **34,309.43 s**.

Those results motivate asking what the measured state cannot identify.
They do **not** establish that hidden running-service duration was the
actual cause of failure in either observational dataset.

The [RP-F006-A01 protocol](../preregistration/RP-F006-A01.md)
was frozen on `main` in commit
[`3670d7d`](https://github.com/DevHabito/relational-persistence/commit/3670d7d9bb15e69c6d354f056ecc4de87b27d55c)
**before new code, numerical evaluation, or Lean proof**.

## Prespecified two-world FCFS-compatible construction

All times in synthetic seconds. Both worlds have one queue, one server,
identical job requests of one processor and requested walltime 500
seconds, and the same complete source event history up to the target's
submission at `t=0`.

| Event | World SHORT | World LONG |
|---|---:|---:|
| Historical H submits | -201 | -201 |
| H starts | -200 | -200 |
| H completes | -190 | -190 |
| Running R submits | -31 | -31 |
| R starts | -30 | -30 |
| R completes | **1** | **100** |
| Target T submits | 0 | 0 |
| T starts | **1** | **100** |
| T completes (duration 1) | 2 | 101 |
| Target's observed submission-to-start wait | **1** | **100** |

At `t=0`, R is busy in both worlds with the same already-observed
age of **30 seconds**, and its original requested 500-second walltime
is identical. Its **actual future completion is not known at origin**.
Both durations 31 and 130 fit within the same requested limit.

**Dispatch qualification:** H and R have one second of documented
submit-to-start delay even when the server is otherwise idle. Our
one-server nonpreemptive FCFS-compatible example enforces no
overtaking or overlap and *immediate target dispatch after R
finishes*, but it **does not impose universal work-conserving
immediate dispatch before the target's submission**. The
independent event-driven simulator uses the SAME explicit
one-second pre-origin dispatch eligibility delays in both
worlds; this is a model assumption, not evidence of any
HPC scheduler's actual policy.

## Equality of observable state

The finite exact-rational event oracles establish:

```
q(-120)             = 0  in both worlds
q(-60)              = 0  in both worlds
q(0-)               = 0  in both worlds
started in [-3600,-60) = 1 (historical H only)
past started-job median wait = 1 second
past start rate     = 1/3540 started jobs/second
running R at t=0   = yes, started at -30, age 30
public R walltime   = 500 seconds
target queue/requested size/submit = identical
```

The complete earlier H/R submission, start and H completion
event lists are likewise identical. Their future finish times
are NOT observable at the origin. The three frozen
RP-E011-P01-style predictors therefore produce the same
value in both worlds:

- HISTORY = **1 second**.
- STATIC = **0 seconds**.
- TREND = **0 seconds**.

Independent queued-count implementations use (i) sorted arrays
with strict binary cutoffs, (ii) an event-by-event chronological
sweep, and (iii) the test's direct predicate
`submit < u <= start`. The strict cutoff avoids treating an
arrival or start exactly at the snapshot as already known.
A separate dispatch replay recomputes both schedules and
checks all starts/finishes.

## Formal mathematical conclusion — tight absolute-error bound

Let `h` denote this one common observation and let
`f(h)=p` be any deterministic real-valued prediction
using **only** h. Since the two worlds have waits 1 and 100,

```
|p-1| + |p-100| >= |100-1| = 99

max(|p-1|, |p-100|) >= 99/2.
```

The midpoint `p=101/2=50.5` achieves the minimax bound
`99/2=49.5`, so it is **sharp for this finite pair**.
Only under a separately declared artificial 50/50 weighting
would the corresponding two-world average absolute-error
minimum be 49.5. Neither bound estimates the actual MAE
distribution of any real scheduler.

[Lean 4 source](../../RelationalPersistence/QueueObservability.lean)
encodes the identical *abstract observable record* in two
worlds with different target waits and proves, for **every**
function from that record to a real number, the sharp minimax
inequality. The Lean proof is a direct specialization of the
**existing triangle inequality**, not new mathematical theory.

The code deliberately does **not** assert that Lean proves
the event-simulator's operational semantics. These are
separately checked in exact Python and adversarial tests.
The Lean compilation and no-`sorry` check passed on the
reviewed [PR #45](https://github.com/DevHabito/relational-persistence/pull/45)
at code SHA `1d2b33e` in
[formal workflow #40205365501](https://github.com/DevHabito/relational-persistence/actions/runs/40205365501).
The original implementation merged at `406e923` after **499
Python regressions per version (3.11 and 3.12)** and Lean CI.
The earlier Lean run on PR #45 FAILED to unfold the world
projections via `change`. It was fixed by simplifying the same
declared definitions before applying the already-proved bound.
No witness time or mathematical claim was altered.

## Distinctions from prior literature and claim boundaries

**Established before this project:** residual service time,
service-age information, scheduling policy and resource
requirements affect queue-wait prediction. See:

- Ward Whitt (1999),
  [*Predicting Queueing Delays*](https://doi.org/10.1287/mnsc.45.6.870),
  *Management Science* 45(6):870–888.
- Little (1961),
  [*A Proof for the Queuing Formula: L = lambda W*](https://doi.org/10.1287/opre.9.3.383).
  This is an average stationary queueing identity, **not**
  a per-job exact wait predictor.
- Murali and Vadhiyar (2016),
  [*Qespera*](https://doi.org/10.1002/cpe.3735).
  Prior HPC queue-wait forecasting.

**Specific contribution of RP-F006:** one disclosed,
preregistered finite counterexample, three independent
queue-state checks, independent dispatch replay, sharp
exact-rational error contrast, adversarial negative controls
and machine-checked Lean certificate of its algebraic bound.

**Not established:** statistical significance on external
systems, a causal explanation for E010/E011 empirical
failures, inability to predict *distributions*, universal
limitations for systems with additional observed state, a
new physical theory, or any calibrated empirical meaning
for `C=B/(I*tau)`.

Our next research task should be to specify **which
additional state can be observed causally**, particularly
running resource occupation, remaining-service-time bounds,
scheduler reservations and priority rules, and to test
whether those variables are measurable *before outcomes* on
an independent source. One cannot obtain fresh validation
by retuning models against the already-opened CERIT-SC
heldout labels.
