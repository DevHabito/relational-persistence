# RP-E010-P01 — Preregistered observational task-wait forecasting on HPC2N

**Frozen BEFORE any RP-E010-P01 prediction implementation or
first prediction computation.** The preceding RP-E010-D01
source-only audit inspected schema and provenance **only**,
and produced no target distribution, forecast, or holdout score.

## Research question and scope

For tasks from the independently collected and already
curated HPC2N Seth batch-scheduler trace, does an
unfitted **recent change in the count of recorded
waiting jobs** improve a prediction of a newly
submitted job's *observed submission-to-start
wait time*, relative to BOTH a static waiting-count
proxy and a historical-wait-time control?

This is an **observational batch-scheduler** test with
known confounders, *not* a direct replication of
RP-E007/009's post-injection queue-recovery target.
This is NOT a model of one FIFO server, a
new law of physical stability, or evidence for
`C=B/(I*tau)`.

## Registered event interpretation

All times are SWF seconds relative to that trace's
start. For each 18-column numeric record j:

- arrival/submit `a_j=submit_j`, SWF field 2;
- observed start `s_j=a_j+wait_j`, field 3,
  only if both values are finite and >=0;
- observed target `Y_j=wait_j` (seconds), for
  rows satisfying `submit>=0`, `wait>=0`,
  `runtime>=0`, `allocated_processors>0`,
  and `status==1`; rows with non-eligible
  outcomes remain excluded only by these
  **previously registered source-quality rules**.

For reconstructing an **aggregate recorded**
waiting-job count from the cleaned trace,
include **every** record with nonnegative submit
and wait, regardless of completion-status code
or processor count, since an observed start time
is defined even if eventual termination status
is unknown. Define

`q(u) = #{k: a_k < u <= s_k}`

for snapshot u. This uses the **before-events**
convention at equal-second timestamps: arrivals
and starts recorded exactly at u are not yet
included/removed. The definition must be
implemented by TWO independent algorithms:
sorted submit/start binary search and
chronological event sweep. Every requested
forecast-origin snapshot must agree. Do not
truncate or interpolate unknown queued jobs
from the original full uncleaned cluster.
`q` is an *archive-derived proxy*, not a
directly sensed physical queue state.

Prediction time for j is `t=a_j`. Features
must depend only on events earlier than t:
`q_prev=q(t-120 s)`, `q_last=q(t-60 s)`.
Thus both observed snapshots are before the
target's submission; all jobs submitted in
the same original second share the same
**pre-submission** feature state.

## Frozen local start-rate and historical wait comparator

Use all jobs with observed nonnegative submit
and wait to define the **already started**
set `W_t = {k : t-3600 <= s_k < t-60}`.
This represents 3,540 seconds of *past*
observed job starts, ending 60 seconds
before target submission. It is explicitly
**not** a measurement of processors-per-second
capacity or the service capacity of the cluster.

- `B_t=|W_t|/3540` observed job starts/second.
- `H_t=mean(wait_k : k in W_t)` is a
  past-observed-wait comparator, available
  by the time those jobs started. It is a
  classical moving historical average and
  does not use the current job's Y.
- Retain only target jobs with `t>=t_min+3600`
  and `|W_t|>=1`, where `t_min` is the
  smallest nonnegative submission timestamp
  in the pinned source. These are **feature-
  eligibility** rules independent of the
  held-out target value. Do not impose a
  maximum wait, trim long waits, remove a
  busy regime, or search for a better window.

The three **unfitted** predictions are:

```text
STATIC: Yhat_S = q_last / B_t

TREND:  q_est = max(0, q_last + (q_last-q_prev))
        Yhat_T = q_est / B_t

HISTORY: Yhat_H = H_t
```

Inputs `q_prev`, `q_last`, B, H must be
derived from **events observable before t**,
although the source is retrospective. None
may use target Y_j, its actual s_j, or
outcome labels from jobs that had not
started before t. `Yhat` and Y are
measured in seconds. A job's eventual
status or runtime are used *only for*
eligibility and subgroup reporting, not
to choose a forecast.

## Prospective holdout boundary — no random resplitting

Compute `t_min` and `t_max` from all
nonnegative recorded submission timestamps
in the source (without using wait durations
or any predictor loss). Freeze

`t_cut=t_min + floor(7*(t_max-t_min)/10)`.

Every feature-eligible target with
`t < t_cut` is a chronological
**diagnostic/calibration** sample; every
such target with `t >= t_cut` is
the **untouched 30%-of-time held-out
segment**. If either partition has
fewer than 1,000 eligible task labels,
declare STOP, not a substituted split.

All candidate predictors above have **no
trained coefficients**. A fixed *additional*
constant comparator is the arithmetic
mean of diagnostic target waits only;
its value is frozen before evaluating
held-out losses. Do not tune arrival
lag 60/120, past-history horizon, the
outcome definition, or feature grouping
using any held-out prediction error.
The holdout is archival, not a new
future prospective natural experiment.

## Frozen primary result and failure gates

Calculate ordinary unweighted MAE in seconds
over **ALL** eligible held-out task labels,
including zero waits and extreme waits.
No win rate or median accuracy may
substitute for MAE. The two registered
primary classical comparators are STATIC
and HISTORY; diagnostic-mean constant is
a secondary control.

- `PASS_OBSERVATIONAL_INCREMENT` iff source
  identity, two-state-oracle agreement and
  non-leakage checks pass, `MAE_STATIC>0`,
  `MAE_HISTORY>0`, and
  `MAE_TREND <= 0.90*MAE_STATIC` **and**
  `MAE_TREND <= 0.90*MAE_HISTORY`.
- `NO_REGISTERED_OBSERVATIONAL_GAIN`
  for any otherwise valid result that
  fails this **two-comparator** criterion.
- `STOP_OBSERVATIONAL_AUDIT` for corrupted
  or nonmatching original SHA/bytes, invalid
  SWF structural source compared with D01,
  disagreement of independently implemented
  queue histories, future leakage, invalid
  denominator/label, fewer than 1,000
  accepted targets per chronological block,
  an incomplete original run, nonfinite
  model output or missing original results.

Failures may NOT be repaired by changing
the source file, comparing only favorable
tasks, modifying treatment horizons or
rerunning the original result as a new
"first" attempt.

## Literature, scope and expected objections

Original PWA source:
https://www.cs.huji.ac.il/labs/parallel/workload/l_hpc2n/
and https://www.cs.huji.ac.il/labs/parallel/workload/swf.html

HPC2N used Maui on a parallel cluster.
The stored trace is cleaned and lacks
queue identifiers; therefore there is
no validated single-worker FCFS
backlog quantity. The moving historical
wait predictor is a conventional strong
control for nonstationary scheduling.
Even a positive result would demonstrate
an incremental property of **this**
aggregate derived queue proxy on one
selected historical trace, not proof
of transferable or causal relational
persistence dynamics. A negative
result would be equally informative.
Existing Lean 4 formalizations remain
separate exact mathematical claims;
no new Lean theorem is proposed here.
