# RP-E008-S01 — Prospective independent discrete-event queue transfer stress test

**Registration status:** FROZEN BEFORE writing the RP-E008 simulator, computing
its new numerical outcomes, or executing its first CI study.

## Scientific question and classification

Does the **unfitted two-pre-end-sample backlog extrapolation** that passed
RP-E007's *single-worker localhost HTTP implementation* retain a
preregistered improvement in a **separately written, deterministic
discrete-event FCFS queue model** with varying arrivals and job service
durations?

A passing or failing result concerns **software-model robustness** only.
It is not a physical experiment, an independent hosted service, proof of
external validity or a fundamental relational-persistence law. Existing
RP-E007 observations motivated this study; this is NOT a blinded
replication of that idea. The simulator is a mathematical construction,
so successful simulation is not evidence that a real system obeys it.

## Frozen transfer model and generators

All times are **nonnegative integer milliseconds**, with exact integer
event times and rational predictions. One FCFS worker, unlimited queue,
no drop, cancellation, preemption or external traffic. All interventions
begin at t=0 ms; **arrival submissions end at t=1000 ms**, with no arrival
at or after t=1000. The model's processing-speed change is fully active
before the first workload arrival (not a measured controller reaction
latency). This test does not compute the C-index or compare tau.

Arrival patterns, repeated in each **200-ms** window in [0,1000):

- `uniform`: arrivals at multiples of 5 ms in each window.
- `early_burst`: arrivals every 3 ms in the first 100 ms of
  each window and every 12 ms in the second 100 ms.
- `late_burst`: arrivals every 12 ms in the first 100 ms of
  each window and every 3 ms in the second 100 ms.

For each planned arrival, draw an **integer millisecond jitter**
from {-1,0,1} using the standard-library Python `random.Random`
generator. Clamp the resulting time to [0,999]; sort by
(time,original ordinal); allow simultaneous arrivals and retain
FCFS ordinal ties. Draw service-duration permutations from an
independent seeded generator; the order may change but the fixed
variant support does not.

Independent nominal *pre-change* job service-duration patterns
(all in ms, each of mean 18 ms):

- `constant`: [18].
- `mixed`: [12,18,24].
- `high_variance`: [6,18,30].

The frozen post-change service duration is **half** its selected
pre-change job duration. For a given trial, jobs receive repeated
groups containing each declared pattern value once, with each
group independently shuffled. The fixed **pretrial calibration**
has exactly 120 pre-change jobs in repeated pattern blocks and
gives the exact capacity `B=1000/18` work/s. The corresponding
post-change nominal capacity is `2B`.
This B is **defined by the simulator's calibration oracle**,
not a physical throughput observation. No outcome is used in B.

For arrival profile index i∈{0,1,2}, service profile index
j∈{0,1,2}, and independent replication r∈{0,...,7}, the
frozen two generator seeds are
`arrival_seed=808000+10000*i+100*j+r` and
`service_seed=909000+10000*i+100*j+r`.
No random seed selection or rejection after observing metrics.

The full grid has 3×3×8=**72** trials. The first r∈{0,1,2,3}
are 36 **diagnostic/development** trials; the untouched
r∈{4,5,6,7} are **36 prospective held-out trials**.
The models have **no fitted parameters**; diagnostic data
only test simulator checks and do not tune the predictor.
No RP-E007 measured data are reused as RP-E008 observations.

## Frozen observables and two predictors

Sample the queue state every 25 ms, processing both arrivals
and service completions at that time **before** taking the sample.
The backlog includes queued+currently active jobs, not
completed jobs. The forecast origin is t=1000 ms.
Use exactly the two **observed** samples at t=925 and
t=975 ms (gap 50 ms and age 25 ms), with
`q_prev=q(925)`, `q_last=q(975)`.

Define exactly, in rational seconds:

- `Yhat_static=q_last/(2*B)`.
- `slope=(q_last-q_prev)/(0.050 s)`.
- `q_extrapolated=max(0,q_last+slope*(0.025 s))`.
- `Yhat_trend=q_extrapolated/(2*B)`.

Both are fixed, unfitted, nonnegative, and use only
pre-end observations. The primary outcome `Y` is
the first **sampled** idle/empty state at or after
t=1000 ms, expressed as time elapsed from t=1000,
*confirmed by at least 500 ms of further 25-ms idle
observations*. No new arrivals after 1000; the
independent service-event oracle also computes the
true last completion time and requires the sampled
result to differ from actual drain time by **less than
25 ms**. The sample-based endpoint is not exact
physical recovery. Keep both and do not substitute
one for the other after measurement.

## Required independent audit

- Implementation A: recursively compute FCFS start and
  completion times with `finish_i=max(arrival_i,finish_{i-1})
  + service_i`; derive q(t) from independent counts.
- Implementation B: separate chronological event engine
  with a priority queue, explicit waiting FIFO and one
  active worker, ordering job completions before
  arrivals at the same time; derive every sampled q(t)
  independently. Match exact completion times, **all**
  backlog samples and drain endpoints in every trial.
- Preserve original generated arrival/service input list,
  both derived traces, hashes of each source and output,
  sample time lists, the 120-job calibration, forecast
  features, rational predicted values and original
  exact sampled outcome.
- Audit no arrivals beyond 1000, all work eventually
  completes exactly once, no negative backlog, no
  service before job arrival, exact FCFS order, finite
  sampled dwell and no early predictor input.
- All 72 grid cases and both oracle traces must validate;
  a missing/invalid result yields
  `STOP_SIMULATOR_INVARIANT` for the complete study.
  NEVER drop problematic cases or change seeds to fix
  an unfavorable score.

## Frozen primary decision

Compute **exact rational** mean absolute errors (seconds)
across the 36 *held-out* trials, separately for STATIC
and TREND. A diagnostic-only MAE is secondary.
The threshold remains a **10%** improvement, not
the 41% observed on RP-E007:

- `PASS_SIMULATED_TRANSFER` iff
  `MAE_static>0` and `MAE_trend <= (9/10)*MAE_static`
  and **all** simulator invariants pass.
- `NO_REGISTERED_SIMULATED_TRANSFER` for any other
  valid result, including `MAE_static=0`.
- `STOP_SIMULATOR_INVARIANT` on failed
  source/algorithm/ordering/recovery checks. No
  post-hoc model, gain threshold or workload update.

Secondary predeclared statistics: each arrival and service
profile's exact MAE and direction of gain/loss, the count
of held-out cases where trend wins/ties/loses, maximum
single-case error, and true exact drain time; no claimed
population p-value or physical uncertainty estimate.

## Publication and archival plan

First commit **this protocol alone**. Implement the two
independent engines on a fresh experiment branch. Test
against small manual counterexamples (simultaneous arrivals,
server idle periods, variable job service times and boundary
timestamps), exact rational identities, and mutations to
source events. Only after Python/Lean CI on the exact
experiment branch passes, squash-merge and permit first
`main` run of the dedicated workflow. Archive the **first**
deterministic run's full source/event data and decision
permanently with SHA-256. CI may not quietly regenerate
altered measurements and replace this first run.

Lean 4 regression is required to ensure *older formal
proofs still compile*. RP-E008 introduces NO new Lean
theorem; a successful Python simulation does not count
as a formal Lean proof of a natural-world process.

## Established literature and limits

This study uses classical discrete-event simulation
and FCFS queue recurrences, not newly discovered
relational mechanics. A useful discussion of the
difference between model verification and validation:
[Improving performances of the emergency department
using discrete event simulation](https://pmc.ncbi.nlm.nih.gov/articles/PMC6001262/),
Section 4.3. Also see the existing prior-work ledger
and the RP-E007 classical queue-state comparison.

Transfer across independently implemented *software
models* is not transfer to hardware, a second
independently operated cloud service, noisy field
sensors or actual human behavior. Positive findings
require a separate real-world validation plan.
