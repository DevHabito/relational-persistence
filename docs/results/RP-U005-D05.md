## Chronology

The D04 first original result was already a negative source-gate decision: both full original ZIPs had correct compressed-body SHA-256 and length, but the CSV header step yielded `INVALID_HEADER_QUOTING`. **That original negative decision remains unchanged.** After examining D04's header chooser, I found that an error from the *wrong candidate delimiter* could stop the entire parser, even if the other candidate was valid. A small synthetic header `"A";"B";"C"` reproduces the error under Python's strict comma parser while passing its strict semicolon parser.

D05 was registered only **after** this failure and proposed explanation were already known. The claim is about diagnosis, not a new discovery of physical-system behavior.

## Bounded original evidence

Only the exact original D04 publisher ZIP source URLs were used. Each was requested once as `Range: bytes=0-65535`, with no alternate mirrors, no credentials, no BigQuery, and no full second download. Both requests received HTTP **206**, exactly **65,536 compressed bytes** and a `Content-Range` whose declared TOTAL equals that source's first D04 full compressed ZIP size.

The original report contains the exact observed header-name lists (public schema field names, not CNPJ data values), literal-header SHA-256, both parser outcomes, source URLs, range metadata, member name and compressed-prefix SHA-256. No original **data row** was parsed or persisted; parsing was limited to the first LF-terminated header. Both observed prefixes had semicolon-delimited, quoted column names.

The successful diagnostic therefore **explains the actual D04 rejection at the point it occurred**: the D04 code was too strict about a failed *alternative*, rather than testing the correctly recognized source delimiter. The faulty algorithm should be corrected in a **later, separately registered full-source audit**, not used to rewrite D04's first report.

## What has and has not been authenticated

The D04 original first run authenticated complete compressed ZIP SHA-256 digests, but the D05 **prefixes do not reproduce those whole-file digests**. Matching the TOTAL in HTTP `Content-Range` to D04's earlier byte count is a useful consistency check, **not bytewise proof that all bytes have stayed the same**. No ZIP central directory, full member CRC, source-data-row count, complete source header/value compliance, cross-dataset join or causal outcome was established by D05.

The D05 first original JSON digest printed by its Actions job was `3919f24513fc74e0b9f6f9108da8a8b4c51b9422148d7eda717f2bd94e1a17ff`. The same first JSON body has been preserved at [`first-run/audit.json`](RP-U005-D05-first-run/audit.json), with a separate [index](RP-U005-D05-first-run/archive-index.json) containing the frozen protocol, run/code SHA, first PDF/ZIP-protocol lineage and both prefix hashes. The first Actions artifact is [#13628073985](https://github.com/DevHabito/relational-persistence/actions/runs/42509613295/artifacts/13628073985), containing summary JSON only.

The original D05 workflow executed **12 synthetic header/range negative controls successfully** before requesting the two source prefixes. Its successful workflow exit and source diagnostic do not license any physical or predictive inference.

## Decision for next work

A new D06 full-file source audit can freeze a **corrected delimiter chooser** that:

1. tests semicolon and comma candidates independently;
2. **does not fail when an irrelevant candidate raises** but a different candidate uniquely satisfies the registered required schema;
3. fails on no valid candidate, ambiguous tie, malformed selected header or bad records;
4. still authenticates the complete original ZIP and reads the full CSV to EOF/CRC, with exact resource budgets and negative controls;
5. continues to stop on unexpected data, and reports missingness and one-to-many joins only under separately frozen rules.

This change does not imply the rest of the CSV is healthy. It does not establish full 2026 calendar coverage, valid cross-dataset joins, actual repair actions, real decision overhead, radial-vs-meshed network topology, F2 recovery or any generalized pregeometry law.

**The source investigation advanced because the original negative result was preserved and the fault was tested, rather than discarded or relabeled.**
