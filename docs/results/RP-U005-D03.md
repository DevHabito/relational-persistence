## The specific problem

A previous documentation review found a discrepancy in the ANEEL PDFs delivered to two inspection interfaces. Extracted PDF text from the nominal 2026 resources said July 2026, but the first-page screenshot operation showed the old October 2022 front page even for the new resource URL. I did not know whether the discrepancy belonged to the publisher, the PDF renderer, a cache or an intermediary. A direct download in the original analysis container failed on DNS; it supplied **no evidence about the bytes ANEEL was actually serving**.

A source-only protocol was therefore committed before making the next publisher byte request. It fixed exactly four official resources, 1 MiB per-object limits, HTTPS/same-host restrictions, exact fingerprint and render rules, and three possible first-run decisions. The old web text and screenshots were **already known**, so the study is a reproducibility and provenance check, **not** a fresh blinded prediction.

## What the original source run did

One GitHub Actions job running Python 3.11 downloaded, sequentially, the four **distinct first-party publisher URLs** named in the [frozen protocol](../protocols/RP-U005-D03-ANEEL-PDF-IDENTITY.md). It used a bounded standard-library HTTPS client and PyMuPDF **1.26.5**. It did not request external incident records, paid services, API credentials, historical scheduler tables, network state or repair outcomes.

The job first executed 15 synthetic PDF/control tests: **15 passed**. The log also includes five warnings from the testing environment; these were not recorded as failures or silently described as additional passing tests. Then it downloaded the four publisher PDFs, checked the complete PDF header/trailer, parsed and rendered the first page from each exact byte sequence, and reported the returned HTTP status, source bytes, raw SHA-256, header version/date, page counts and raster hashes. All four HTTP responses were **200**, used `application/pdf`, and retained the same original official download URLs. Each PDF was below the registered 1 MiB limit and was parseable.

The complete original per-document records, including rendering/text fingerprints, are preserved as first-run [`audit.json`](RP-U005-D03-first-run/audit.json) and [`archive-index.json`](RP-U005-D03-first-run/archive-index.json); the raw public source PDFs and first-page PNG renders were placed in the linked **90-day** Actions artifact, not reproduced as bytes in Git.

Both 2026 PDFs are demonstrably different from the pre-2026 resources in their original SHA-256, page-raster fingerprints and header dates. **The interruption dictionaries both call themselves version 1.0 but are still distinct official files, issued in different years.** Version numbering alone must not serve as a file identity.

The local second audit independently downloaded the first hosted Actions artifact from GitHub, opened its ZIP in a fresh container, and verified:
- the ZIP SHA-256 equals the original Actions job-log SHA-256,
  `73dd97df0a0d3119790ef855e14d503a165da0b121861510ba59fa343396a49e`;
- its untouched original `audit.json` (4,953 bytes) hashes to
  `1243c3389b5800035d7feac93c91bfc0ca18c789cd1fd3ab94b5d0efe95274fa`;
- **all four PDF bytes** and independently computed whole-object SHA-256 values match the first-run JSON entries;
- the first-page PNGs of **both new dictionaries** visually display July **2026**, rather than the 2022 headers shown by the previous web screenshot operation.

This corroborates which file contents the publisher served to this hosted runner and what the same bytes render locally. It does **not** identify the internal cause of the earlier screenshot mismatch. The evidence supports attributing that observed inconsistency to the *inspection path used in the earlier attempt*, not asserting that the ANEEL source bytes had been 2022, were corrupt or were changed to make this test pass.

## Original archive integrity

The first source code produced JSON and the hosted run printed a SHA-256 of that exact JSON. A byte-for-byte reconstruction of its printed original JSON has been added to `docs/results/RP-U005-D03-first-run/audit.json` without changing the first-run contents. The paired index anchors the original job, code SHA, protocol SHA, complete PDF fingerprints, original report digest and the artifact name, identifier and ZIP digest.

A separate `tests/test_rp_u005_d03_first_archive.py` tests the original report byte SHA against its **independently fixed expected digest**. A corrupted report must fail even if someone edits the associated manifest to match the corruption. The test also checks the four exact published source digests, document sizes, header dates, page counts and no-incident-data boundary. These regression tests do not pretend to re-download the PDFs on each run.

## What this resolves and what it does not

**Resolved within this bounded source gate:**

- The same first-party links return **four distinct complete PDF sources** with the expected category and generation-era headers.
- The four exact PDF bodies, first-page rendering hashes, first-run JSON and original artifact ZIP have independently checkable SHA-256 fingerprints.
- The previous screenshot-versus-extracted-text discrepancy is not evidence that the publisher was serving identical old 2022 documents at those URLs at the time of this direct run.
- The old- and new-era dictionaries cannot safely be combined by a careless column rename.

**Still unverified:**

- The exact live schemas, completeness, field missingness, CNPJ/occurrence joining or duplicates **inside the large original 2026 ZIP/Parquet event files**. **Zero** ANEEL operational event rows were read.
- Whether `CodOcorrencia` and `CodOcorrenciaEmergencial` join one-to-one, one-to-many, or incompletely in original records; despite official descriptive cross-references, an actual-data join has not been computed.
- Whether BDGD's annually published topology describes actual energized switching states and restoration paths at individual incident times.
- Whether historical operator receipt times, individual restoration decisions, alternative feasible actions, decision compute costs and an independently observed F2 functionality are available.
- Whether two *simultaneously energized* vertex-disjoint paths make operational sense in commonly radially operated feeders; an installed normally open backup tie is not a concurrently energized route.
- Any real operational gain, novel mathematics, universality across systems or a physical `C=B/(I*tau)` relation.

The source-only classification is a **real positive result about document identity**, not a positive result about network repair, ecology, physics, or predictive utility.

## Prior definitions and next registered gate

The relevant original issuer is ANEEL, under its publisher catalogs for [emergency occurrences](https://dadosabertos.aneel.gov.br/dataset/ocorrencias-emergenciais-nas-redes-de-distribuicao) and [electricity interruptions](https://dadosabertos.aneel.gov.br/dataset/interrupcoes-de-energia-eletrica-nas-redes-de-distribuicao). These official dictionaries already define the original category and field terminology; they are the primary evidence, not a new contribution from this project.

To proceed into actual observed incident records, a **different**, separately frozen *source-only* protocol must fix which **specific** ZIP/Parquet revision is acquired, its timestamp range, maximum bytes, header schema, audit digest, original row counts, duplicate/invalid-key decisions, missingness rules, and what constitutes irreducible mismatches. Since the 2026 catalog resources are hundreds of MiB and the year may be incomplete, resource feasibility and a first-run negative access result must both remain admissible.

No endpoint forecasting or model fitting is authorized by this document. A further observational outcome protocol must come **after** a verified source gate and must use historically available features and relevant established baselines. The original frozen U004 synthetic result cannot be repurposed as an independent field confirmation.

**Regressions on the eventual archival PR head:** recorded in PR #75 only after the corresponding checks complete. The first original-source workflow is already independently documented above, and must not be silently repeated or overwritten if later documentation is revised.
