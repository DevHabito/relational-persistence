## Frozen event semantics and temporal snapshot audits

For each original machine line require:
- a JSON object, strict decimal strings for `time`,
  `machine_id`, `type`;
- unsigned nonnegative trace-relative microsecond `time`,
  machine ID nonnegative integer string, event type
  1=ADD, 2=REMOVE, 3=UPDATE; any unknown event
  or missing core field -> reject whole original result;
- `missing_type` if present: decimal-string code 0..5;
  nonzero flagged rows are NOT exact observed transitions;
- `capacity` may be ABSENT; never impute missing
  capacity as zero or infer complete resource inventory.

Implement two INDEPENDENT event parsers/counters:
(A) `json.loads` + canonical integer validator;
(B) a separate source-line structural/decimal validator,
with independent state sort reconstruction.
They must agree on event counts, last-event category,
same-entity/same-timestamp tie contradictions and two
fixed before-origin snapshots. They may share decoded
records only after their independent row validations.
No observed machine IDs, obfuscated names or raw events
may enter the Git report.

Use exact fixed snapshot origins (trace-relative microseconds):
`T1=1_000_000_000_000` and
`T2=2_000_000_000_000`.
A source event is available ONLY if
`event_time < origin`; equal-time events excluded.
For any machine whose latest **nonflagged** event strictly
before origin is ADD or UPDATE, report as
`last_event_implied_active`; REMOVE implies
`last_event_implied_removed`. If multiple events share
the latest machine/time with DIFFERENT types, classify
`ambiguous_last_event_tie` and do not infer state.
If latest event has a nonzero missingness flag, state
`uncertain_due_to_reconstructed_event`.
If no earlier event, report `no_prior_event`.
Sort by `(time,machineID,type)` only to make
aggregated consistency checks reproducible; do not
infer provider within-timestamp causal order.

Count all source events per type, missing-flag distribution,
rows with capacity present, original adjacent timestamp
inversions, same-machine/same-timestamp tie groups,
conflicting-type groups, unique observed machines
(aggregate count only), and temporal snapshot
classification counts. Cross-check two independent
methods with exact integer counts, not tolerance.

**Important:** even after complete machine_events
media verified, snapshot counts are solely
`event-implied` within a particular published
stream. We cannot prove online event delivery
at the recorded time, initial completeness,
machine capacity configuration or full scheduler
state. `SCHEDULE` from instance_events is a
placement event, not actual process start.

## Registered decisions (precedence) and falsifiers

1. `SOURCE_ACCESS_BLOCKED` if any of the three
   required anonymous metadata pages or selected
   machine media cannot be reached with no-cost
   anonymous HTTPS, or if provider requester-pays.
2. `MACHINE_SOURCE_COVERAGE_UNVERIFIED`
   if the original machine inventory has
   pagination, zero/multiple matching machine files
   or size >2 MiB.
3. `MACHINE_SOURCE_IDENTITY_REJECTED`
   for fixed object byte count, generation,
   provider MD5/full gzip trailer mismatch.
4. `MACHINE_EVENT_FORMAT_REJECTED` for invalid
   source row/gzip/UTF8/size or event schema.
5. `MACHINE_EVENT_CONSISTENCY_REJECTED`
   if independent parsers or state counts disagree.
6. `MACHINE_EVENTS_COMPLETE_OBJECT_AUDITED_JOINT_UNCERTIFIED`
   **only** if all machine-file gates pass and
   the two independent temporal oracles agree;
   it certifies the single full, first-page
   unpaginated *machine_events* object contents,
   not a full causal scheduler state.

Both contradictory ties and nonzero missing flags
are **adverse observations**, NOT automatically
format errors, and must stay recorded exactly;
do not remove such rows for a favorable result.
The final flag `JOINT_CAUSAL_HISTORY_NOT_CERTIFIED`
must be true for ALL outcomes: collection/instance
source bodies are intentionally NOT read.
No performance target, training, forecasting
or causal effect of a resource cap is tested.
