## Context, novelty and explicit prior work

RP-F006-A01 (preregistered at `3670d7d`, original first run
`40205665104`, original archived result `caab6ad`) establishes a
finite, synthetic, non-work-conserving-before-origin FCFS-compatible
two-world example: identical pre-origin information and waits 1 and 100.
Lean 4 proved a sharp 99/2 second two-world minimax error lower bound.
This is a standard triangle-inequality fact, not new queueing theory.

RP-E010-P01 and RP-E011-P01 remain two independent negative external
forecast findings. RP-F007 DOES NOT retune or rescore their holdouts.

Prior art:
- Ward Whitt, *Predicting Queueing Delays* (1999), Management Science
  45(6):870–888, https://doi.org/10.1287/mnsc.45.6.870.
  Conditional residual service and elapsed running service are known
  queue-forecasting factors.
- SchedMD, official Slurm sbatch `--time` documentation,
  https://slurm.schedmd.com/sbatch.html, explains requested/assigned
  walltime, termination, and possible OverTimeLimit extension.
- SchedMD, official `slurm.conf` documentation,
  https://slurm.schedmd.com/slurm.conf.html, describes the MaxTime
  and admin-adjustment settings.

We claim **no new minimax theorem**. Our project-specific
contribution is a frozen finite demonstration plus independent
causal-observation audits and a Lean certificate that explicitly
separates an *enforceable* hard runtime cap from a mere requested
walltime. A verified synthetic gate is not an empirical validation
or a universal persistence law.

## Exact registered model and finite families

Inherit RP-F006's single-server, nonpreemptive FCFS-compatible
three-job schedule:
- H submits -201, begins -200, completes -190;
- R submits -31 and starts -30, is running at target submission t=0;
- T submits at 0, requests one processor, and starts immediately when
  R completes, then runs for 1 synthetic second.
- H/R have the same fixed one-second pre-origin dispatch eligibility
  delays as RP-F006; NOT globally work conserving.
- Queue, all arrival/start/history events, target requested CPU,
  target run duration and target public requested walltime are fixed
  *within* each family.
- R has age **30 seconds** at origin. Its *actual* service duration
  is exactly `30+r`, with integer future remaining time
  `r in {1, ..., L-30}`, where `L` is a fixed **enforceable
  hard runtime cap** known to the observer *in that family*.
- One job at a time, no new arrivals, no preemption, no pauses,
  no priority overrides, no alteration of walltime after origin,
  and immediate dispatch of T when R ends. Thus T wait = r.

**BROAD** cap L=500 (effective maximum residual R=470).
All 470 integral worlds r=1..470 are admissible, have identical
pre-origin event records and identical public hard cap 500.
Their common causal input includes R's age 30 and L=500,
but NEVER its actual future runtime or end time.

**NARROW** cap L=90 (effective maximum residual R=60).
All 60 integral worlds r=1..60 are admissible, have identical
pre-origin records and identical public hard cap 90.
They differ from BROAD in the **known** hard upper limit. Thus
we do NOT claim the two different-cap families share all inputs.

H and T each retain the same separate synthetic publicly requested
walltime 500. Only R's public enforced cap differs between the
two families. The origin is 0 and time units are synthetic seconds.

## Registered questions and falsifiers

1. All 470 + 60 distinct world schedules must pass exact-rational
   validation of FCFS start order, service non-overlap, R being busy
   at origin, requested resource equality, positive durations,
   R actual duration <= respective hard cap, and exact equality
   of every public pre-origin event/input within its family.
   Independently reconstruct starts/finishes from FCFS dispatch,
   and verify waiting-count snapshots using two separate
   implementations. Any failure means `BOUND_WITNESS_INVALID`.
2. BROAD observed waits must be the complete INTEGER set
   `{1,...,470}` exactly (no truncation). NARROW observed waits
   must be `{1,...,60}` exactly. Both observations may support
   *set-valued prediction*, not exact individual waiting-time
   identification.
3. For every deterministic real-valued predictor p that uses only
   BROAD's shared observed state, the worst-case absolute wait
   error over 470 possible worlds is at least **469/2 = 234.5 s**.
   Exact fixed midpoint p=471/2=235.5 s attains this minimax
   error across ALL possible worlds, not just endpoints.
   For NARROW, minmax error is **59/2 = 29.5 s**, attained at
   midpoint p=61/2=30.5 s across ALL 60 worlds.
   Python must compute both exhaustive integer-domain results
   with exact Fraction and independent analytical endpoint formula;
   no floating tolerance or parameter fit.
4. Lean 4 must prove the unrestricted real-predictor lower bounds
   from the two feasible extreme worlds, midpoint upper bounds
   FOR EVERY real wait in the registered closed intervals
   [1,470] and [1,60], and sharpness. It may use classical
   triangle inequality, `linarith` and `norm_num`; no
   `sorry`, `admit`, or added axioms. It need not prove the
   whole Python scheduler implementation: that is a separately
   tested operational assumption.
5. Registered counterfactual benefit in minimax worst-case
   *synthetic* absolute error: with cap L=500 -> **234.5 s**;
   cap L=90 -> **29.5 s**; arithmetic difference **205 s**,
   ratio of new to old **59/469**. This change is valid
   ONLY for the separately observed enforced-cap populations
   and is not a real-world causal estimate.
6. NEGATIVE CONTROLS:
   (a) If walltime 500 is merely a public *request* and is NOT
   guaranteed/enforced, create otherwise identical valid
   FCFS dispatch histories with r=471, duration=501 >500.
   This MUST fail the hard-cap admissibility gate. We do NOT
   infer any finite 470-second wait bound from an unenforced
   advertised walltime.
   (b) A causally illicit oracle given future actual end time
   predicts exact T wait with zero error; identify that this
   input is unavailable before origin.
   (c) A proposed prediction of 0 for BROAD is outside the
   admissible wait set; its maximum absolute error must be
   exactly 470 s.
   (d) Altered registered server dispatch timing/overlap,
   forgotten age/cap or a hidden future arrival must fail
   the strict audit.
7. All records must explicitly distinguish PUBLIC CAP,
   ACTUAL SERVICE (hidden pre-origin), FUTURE END (hidden),
   and MAXIMUM POSSIBLE RESIDUAL (computable only if the
   cap is guaranteed). Never leak hidden values into a
   predictor by reading entire source data before the
   causal knowledge boundary. The offline simulator naturally
   knows all labels, but only the declared PUBLIC OBSERVATION
   may enter the interval prediction.

Registered decision `BOUNDED_STATE_MINIMAX_VERIFIED`
**only if all seven gates pass**. Else
`BOUND_WITNESS_INVALID` with the failure reason recorded;
never revise cap values or endpoints within A01 to secure a pass.
There is no empirical dataset, training set, holdout MAE,
or new physical persistence scalar `C=B/(I*tau)` test.
