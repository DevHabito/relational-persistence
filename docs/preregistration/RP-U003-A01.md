  https://doi.org/10.1038/nature18019).

**New scoped question:** under EXACTLY the same edge-reconstruction budget,
does a fixed deterministic two-step lookahead rule that considers the
specified source-target function improve total F1 connectivity uptime across
an EXHAUSTIVE small-graph ensemble compared with degree-only and label-order
baselines? How often does it lose, and how much room remains to an
offline combinatorial optimum? This is an already studied type of repair
optimization, NOT an attempt to rename it as a new universal law.

## Entire fixed graph ensemble — NO hand-picked favorable examples

Vertices V = {0,1,2,3,4,5}, protected source s=0 and target t=5.
Undirected, loopless, simple unit edges. Consider ALL subsets of exactly
SEVEN distinct edges of the 14 unordered pairs among six vertices
EXCLUDING direct terminal edge (0,5), enumerated lexicographically.
Admit exactly those graphs satisfying:
(1) source degree exactly TWO;
(2) destination degree exactly TWO;
(3) ALL six vertices lie in ONE connected component.

No additional learned threshold, topology filter, randomness, manual network
selection, sparse/dense subgroup preference or exception for tie outcomes.
Enumerate this labeled family with TWO INDEPENDENT enumeration methods:
A = itertools.combinations of the 14 pairs, length 7; B = integer bit masks
over the same 14 edges filtered by population count=7. Exact accepted graph
edge-tuple set equality is REQUIRED. Report the computed ensemble size N,
canonical SHA-256 of all accepted graph edge tuples, terminal degrees,
and full degree histogram. There is no frozen expected N: the two independent
enumerators must agree exactly and N must be >0. The family is LABELLED:
all internal-node relabelings may appear, so aggregated scenario counts
are **not a statistical independent sample or unlabeled-graph census**.
Ascending-ID strategies can depend on labels; disclose, don't correct after.

For EACH admitted graph, test EVERY one of the four internal failure
identities v in {1,2,3,4}, independently reset to original graph.
This defines exactly 4N source-loss scenarios per policy. There is
NO choice of favorable target after viewing results.

## Exact discrete failure/repair timeline and common budgets

t=0 original 6-vertex, 7-edge graph; t=1 remove original v and ALL
incident edges. At t=2 introduce distinct replacement identity 6+v.
At t=2,3,4,5,6 respectively add ONE new edge from replacement to
a different former neighbor of v while any unrebuilt neighbor remains;
otherwise no edge. Original v NEVER returns. The original neighbor
set is a known static public repair blueprint at t=0. Every policy
must use exactly min(t-1,degree_original(v)) restored edges by time t>=2.
No edge formation outside v's original neighborhood, no resource flow,
no hidden future observations and no other failures.

Time is a DIMENSIONLESS model tick, not days/seconds, and a new
node is added at t2 regardless of which policy is used. For any
given (graph, lost v, t), all policies MUST have IDENTICAL present
component COUNT, edge COUNT and cumulative repair cost (one unit
per rebuilt edge), though the particular links differ. No repaired
source/destination or old identity resurrection.

Policy options, fixed independently of observed scores:
- ASC: attach original neighbors in numeric ascending order.
- DEGREE: attach by DESCENDING original pre-loss degree, ties
  ascending numeric vertex ID. Degree is original full-graph
  incident edge count, not future dynamically recalculated data.
- GREEDY1: at each repair tick choose among ALL still-unused
  original neighbors the candidate whose immediate prospective
  one-link state maximizes lexicographic (F1,F2);
  ties ascending numeric neighbor ID. This rule explicitly
  uses the terminal function, unlike degree-only control.
- LOOKAHEAD2: at each repair tick, for each candidate a,
  consider state after a, then the BEST one additional
  possible distinct neighbor b at the next tick (if any).
  Rank a by lexicographic (best_future_F1,best_future_F2,
  immediate_F1,immediate_F2); ties ascending numeric neighbor.
  This uses only the known current source graph and
  hypothetical available actions, not hidden empirical
  future data. For the final neighbor, the future state
  equals the immediate state. The two Boolean functions
  and this EXACT tie ordering are frozen.

Operational F1 = at least one undirected simple 0-to-5 path;
F2 = at least TWO internally vertex-disjoint simple
0-to-5 paths. F2 always implies F1. For EVERY unique
repaired state use TWO independent F1 oracles (BFS and
independent DFS path enumeration) and TWO independent
F2 oracles (interior-disjoint path-pair search and
single-internal-vertex deletion BFS for these graphs,
no direct 0-5 edge). Exact agreement is required.

Reference bounds (NOT deployable competitor policies):
- OFFLINE_F1_ENVELOPE(t): evaluate every subset of
  original lost-node neighbor edges with exact size
  min(t-1,degree(v)); maximal F1 among them.
- OFFLINE_F2_ENVELOPE(t): same procedure maximizing F2.
  These are separate function-specific per-time
  upper bounds, not falsely advertised as a
  single attainable multi-objective policy.
  The original graph, all possible repair edges and
  the evaluation function are PUBLIC to this toy
  optimization; do NOT report a prediction about real
  future events from this offline oracle.

No separate NO-REPAIR arm: unequal budgets would
undermine the study's primary equal-budget comparison.
Old U002 no-repair results remain preserved as prior art.

## Registered primary and adverse comparisons

Primary unit: exact micro-average F1 uptime across ALL
accepted graphs, ALL 4 failures each, and t=1..6
(SIX after-failure ticks). Denominator = 6 × 4 × N.
Report integer sums, not invented probabilities or uncertainty.

Primary H1 is **DIRECTIONAL**:
LOOKAHEAD2 must strictly exceed BOTH ASC and DEGREE
in total F1 uptime, under identical repair cost.
If it ties OR loses to either, declare
`REGISTERED_LOOKAHEAD_F1_ADVANTAGE_NOT_SUPPORTED`.
Even if H1 passes, the finding is an IN-SILICO finite
comparison of existing repair strategies, not
a novel law or generalizable empirical improvement.

Secondary, predeclared analyses:
(a) GREEDY1 vs other rules on F1;
(b) F2 total uptime for all policies;
(c) exact regret to the F1 and F2 offline
per-tick envelopes, which every policy must
not exceed at ANY scenario or tick;
(d) per-case LOOKAHEAD2 wins / ties / losses
versus ASC, DEGREE and GREEDY1 on integrated F1;
(e) count of cases where LOOKAHEAD2 has
LOWER F1 uptime than at least one simpler rule
(negative counterexample; no exclusion);
(f) degree-sequence strata of wins and
losses, with true case counts;
(g) for each original loss case, equal
node/edge cost trajectories at all snapshots;
(h) all-event trace SHA-256 over a deterministic
JSONL encoding of original artificial graph,
failed node, fixed per-time F1/F2 and costs
for each policy, with a separate aggregated report.
No data-derived tuning or post hoc "best subset".

Scientific distinction: lookahead uses MORE task knowledge
and potentially MORE computation than ASC/DEGREE.
Equal EDGE BUDGET is NOT equal information,
CPU-time or algorithmic complexity. Measure
total candidate evaluations as a compute-effort
indicator (deterministic code check count),
but do NOT pretend equivalent computational cost.
No real systems or stochastic draws. Under this
closed-form model a sensible existing optimizer may
match/exceed proposed lookahead; negative
results must be highlighted, not repaired.
