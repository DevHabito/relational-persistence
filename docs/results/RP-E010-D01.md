wait and runtime; positive allocated processors; and

## Limits before any real-world forecast

1. **The archive was cleaned upstream.** Its curator
   removed 324,500 records using documented filters,
   including anomalous user bursts. Treating the
   resulting trace as the untouched, representative
   production history would be incorrect.
2. **No per-queue IDs remain.** We cannot reconstruct
   queue-specific states or scheduler disciplines
   from the missing field. We can investigate at most
   a proxy for *aggregate recorded waiting jobs*
   based on prior submission and start events, with
   incomplete coverage after cleaning.
3. **Heterogeneous parallel scheduling.** This was
   a multiple-node production cluster with Maui,
   not a single FIFO worker. Snapshot backlog
   divided by an observed start rate will be a
   rough classical engineering comparator, not
   a rigorous multi-resource queueing prediction.
4. **Historical rather than live observation.**
   Submit and wait timestamps are documented
   archival fields. Their causal ordering can
   support a *retrospective held-out* observational
   prediction study, but not an online production
   prediction claim without independent deployment.
5. **Mirror identity is not upstream byte identity.**
   We verified the pinned mirror's exact Git blob,
   not whether it is byte-for-byte equivalent to
   the university's separately hosted compressed
   original. Preserve that distinction.

The NASA iPSC/860 workload was explicitly
**excluded** for arrival-based analysis:
its converter substituted start timestamps
where real submit timestamps were missing.
See the [NASA conversion notes](https://www.cs.huji.ac.il/labs/parallel/workload/l_nasa_ipsc/)
and [SWF field definitions](https://www.cs.huji.ac.il/labs/parallel/workload/swf.html).
