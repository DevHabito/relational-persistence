# RP-F007-A01 — Enforced walltime reduces a synthetic worst-case wait bound

**Original first-run decision: `BOUNDED_STATE_MINIMAX_VERIFIED`.**

This is an **exact, finite, synthetic demonstration** of an established
queueing/decision-theory principle: a causally observable, **guaranteed**
service upper bound can shrink the admissible uncertainty interval.
It is not new minimax mathematics, a real scheduler result, a queue
forecast improvement measured in the field, or a physical law.

## Model and exactly what the observer knows

The synthetic model inherits RP-F006's declared *single-server,
nonpreemptive, FCFS-compatible*, three-job sequence:
H submits -201, starts -200, ends -190; R submits -31, starts -30;
target T submits at 0 and begins immediately after R completes.
H and R had fixed one-second pre-origin dispatch delays, so
**global work conservation before origin is not asserted**.
There are no additional arrivals, policies, reservations, pauses,
preemption or future changes to the effective runtime cap.

R is **already running for 30 seconds** at the origin. Its
public cap `L` is known and **enforced**; actual duration is
the hidden `30+r`. The target's wait equals hidden future
residual `r`. Every possible remaining time is integral,
`r = 1, 2, ..., L-30` seconds; this finite integer-time
restriction is a **declared model choice**. All public events,
queue snapshots, historical waits, request sizes and R's public
cap are identical *within* each family.

The narrow and broad groups have **different** public caps,
hence **different public observations**. This is not a
same-input comparison and is not a randomized causal experiment.
The Python audit verifies all 530 schedules through a separate
dispatch replay, three queue-state implementations and a
full equality comparison of pre-origin public observations
within each cap group.

## Registered result — complete exact-rational families

| Registered source assumption | Enforced L=500 s | Enforced L=90 s |
|---|---:|---:|
| Already elapsed R service | 30 s | 30 s |
| Admissible remaining times | all integers 1..470 | all integers 1..60 |
| Independently validated worlds | **470** | **60** |
| Minimum possible target wait | 1 s | 1 s |
| Maximum possible target wait | 470 s | 60 s |
| Minimax point forecast | **471/2 = 235.5 s** | **61/2 = 30.5 s** |
| Sharp worst-case absolute error | **469/2 = 234.5 s** | **59/2 = 29.5 s** |
| Point forecast 0: worst error | 470 s | 60 s |

The exact mathematical reduction in minimax worst-case absolute
error is **205 seconds**, leaving a bound ratio of **59/469**.
This is a difference between **two hypothetical assumed and
enforced source populations**. It must NOT be reported as
a 205-second performance gain achieved on actual HPC workloads.

All waiting times in the two admissible integer grids were
checked, rather than selecting just favorable examples. The
Python `Fraction` enumeration and separately derived
endpoint formula agreed without floating tolerances.

## Lean 4 theorem: sharp real-valued interval minimax, conditional

The file
[`RelationalPersistence/ResidualBounds.lean`](../../RelationalPersistence/ResidualBounds.lean)
encodes the public hard-cap state, equal observations for the
two extreme worlds *within* each cap group, and unequal public
states **between** the two caps. It proves:

```
For any real p:
 max(|p-1|, |p-470|) >= 469/2,
 max(|p-1|, |p-60|)  >= 59/2.

For every real w in [1,470]:
 |471/2 - w| <= 469/2.

For every real w in [1,60]:
 |61/2 - w| <= 59/2.
```

The two endpoints make each bound **sharp**; any deterministic
function of the shared public input must have the same output
in both endpoint worlds. Lean proves the algebraic result for
all real-valued predictors and every REAL waiting value in
the specified closed intervals; the external Python simulation
checks model-specific feasibility of integer worlds separately.
The interval statements are classical triangle-inequality
consequences, not novel theorems. No missing proof is
replaced by an unverified `sorry`, `admit` or new `axiom`.

The Lean module intentionally **does not formally verify the
scheduler simulator code or guarantee that a real job limit
is enforced**. That latter condition is a model assumption
which must be independently verified before any practical use.

## Adversarial controls and the critical walltime distinction

The original audit verified every fixed negative control:

- A reported R walltime of 500 with actual service duration
  **501** and remaining wait **471** is a valid
  FCFS-compatible *advertised-only* trace, but **fails**
  the strict hard-cap admissibility check. Thus an arbitrary
  requested walltime is NOT a certified upper bound.
- Revealing R's *future actual completion* gives an
  artificial perfect oracle. It is NOT a causal feature
  available to a real submission-time predictor.
- An always-zero point forecast has registered worst-case
  errors **470** and **60**, and therefore is not
  mislabeled minimax optimal.
- Unknown additional jobs, shifted dispatch/age, service
  overlaps, and changes to the registered populations or
  hard limits are rejected by the audit rather than ignored.

This difference is realistic enough to require caution:
official [Slurm sbatch](https://slurm.schedmd.com/sbatch.html)
and [slurm.conf](https://slurm.schedmd.com/slurm.conf.html)
documentation describe configurable time limits, possible
administrative modification and `OverTimeLimit` settings
that permit runtime beyond the nominal value. Slurm is
prior technology, not the scheduler implemented here;
we **did not verify** any real installation's settings
or treat an archived requested walltime as proof of
live enforcement.

## Knowledge added, and knowledge still absent

**Verified within model:** conditioning on an enforced,
public upper bound and the already-known service age
narrows the feasible future-wait set. A sharp minimax
absolute-error point prediction exists for the specified
finite, single-server case.

**Not verified:** empirical calibration of residual service,
scheduler-wide admission/scheduling policies, multiple
concurrent jobs, changing reservations, resource contention,
uncensored waiting-time distributions, or forecast MAE
on an independent workload. Neither a true stochastic
remaining-runtime distribution nor a hardware intervention
was provided.

Earlier negative RP-E010-P01 and RP-E011-P01 observational
heldout results are still negative. RP-F006's finite
nonidentifiability result is still valid: even with an enforced
cap, the current wait is generally not *point-identifiable*
because many admissible residuals remain.

No physical relational persistence `C=B/(I*tau)` was
calibrated, independently tested, or established.
No universal law or new queuing-theory priority is claimed.

## Prior-art boundary and next meaningful research gate

Ward Whitt (1999),
[*Predicting Queueing Delays*](https://doi.org/10.1287/mnsc.45.6.870),
established how service-age information and conditional
remaining-service distributions can improve waiting-time
prediction. The minimax midpoint of a deterministic
bounded interval is elementary decision theory.

A distinct future practical study would need a NEW
independently sourced log with **historically available
snapshots** containing assigned time limits, when they
were applied/modified, observed service age, actual
resource occupation, scheduling order, and verified
hard-limit enforcement/overrun behavior. It should
preregister missingness and temporal split before
comparing any predictive loss. The already-scored
CERIT-SC 169,189-job holdout is no longer unseen and
must not be used to claim fresh validation.
