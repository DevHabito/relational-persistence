# RP-E002-A01 — Registered observed-trajectory forecasting benchmark

**Registration status: FROZEN BEFORE TEST-DATA ANALYSIS.**
This is a prospectively specified *secondary* observational benchmark
about useful graph topology in traffic-speed forecasting. It is **not** a
test of the original capacity-noise-latency quotient and does **not**
replace or retrospectively revise RP-001.

Publication of this document must precede all code-driven inspection
of the METR-LA test outcomes. The Git commit creating this document is
the immutable registration anchor; changes require a clearly labeled
new protocol, not a silent edit.

## Research question, null, and alternative

**Question:** For observed METR-LA traffic-speed time series, does
one-hop spatial mixing along an externally supplied fixed sensor graph
improve held-out multi-horizon forecasting over *both* strong
topology-blind baselines and a sensor-relabelled graph control?

- **H0 (no registered improvement):** at least one of the required
  comparisons below fails.
- **H1 (restricted improvement):** the graph model improves on the
  stronger of last-observation persistence and training-only historical
  weekday/time-slot mean by **at least 1%** in sensor-balanced MAE,
  and beats a separately validation-tuned sensor-relabelled graph by
  **at least 1%**, at **every** horizon of 15, 30, and 60 minutes.
- The effect threshold and conjunction across horizons are fixed here.
  A single missed horizon counts as failure; an exact tie is failure.
  Results must report actual signed differences, not just a pass/fail.
- Any result is about predictive utility on this particular archive.
  A positive result is **not** causal recovery, a universal stability
  theorem, a new traffic model discovery, or a validation of `B/(I*tau)`.

## Fixed model definition

Let `x[t,j]` be the observed speed at timestamp `t`, sensor `j`.
The three registered horizons are `h={3,6,12}` five-minute intervals.

- **Persistence baseline P:** `forecast[t+h,j]=x[t,j]`.
- **Training-only seasonal baseline S:** historical per-sensor mean
  of positive finite speeds at the target weekday and five-minute
  clock slot, estimated exclusively from the *training period*;
  fallback to the same sensor's positive training mean if its
  target slot has no training observations. Sensors lacking a
  valid fallback trigger a data-quality stop.
- **Graph model G:** `(1-lambda)*x[t,j] +
  lambda*neighbor_average[t,j]`, where the average is computed
  from **available positive finite source speeds at time t only**.
  With no observed graph neighbors, use the current sensor
  observation unchanged. Graph edge weights come solely from
  the externally supplied fixed distance file and DCRNN's
  threshold rule: `w_ij = exp(-(distance_ij/std_cost)^2)`
  if the result is >= 0.1, otherwise zero. The deviation is
  normalized per target row after excluding self edges.
  Distances are not fitted on measured speed outcomes.
- **Negative-control graph G_perm:** use the same G formula, but
  replace the adjacency by `P A P^T`, for a single whole-sensor
  pseudorandom permutation with seed `20261023`. This retains
  the weight matrix's global properties while breaking its
  alignment to sensor identities. Select its lambda separately
  on validation, as a fair competitive control.
- **Lambda selection:** for G and G_perm independently, at each
  horizon minimize validation sensor-balanced MAE on the fixed
  grid `{0, 0.05, 0.10, 0.20, 0.40, 0.60, 0.80, 1.00}`.
  Ties select the **smallest** lambda. Value zero means the
  observed graph was not selected as useful.
- There is no training on test labels. Prediction can depend
  on the *current* observed x[t] during test; never on x[t+1]
  or later.

## Frozen chronological protocol

- Assign complete timestamps to contiguous train (first 70%),
  validation (next 10%), and test (last 20%), using integer
  boundaries `train_end=floor(0.70*T)`,
  `validation_end=floor(0.80*T)`.
- Seasonal statistics are trained strictly on indices
  `0 .. train_end-1`. Lambda is selected only using forecast
  origins `train_end+12 .. validation_end-13`.
- Hold-out evaluation uses forecast origins
  `validation_end+12 .. T-13`; the fixed 12-step embargo
  around boundary comparisons reduces overlap between
  validation labels and test origin windows.
- Each horizon is evaluated on the same forecast-origin range,
  with valid positive finite pairs of current and target
  sensor speeds. Zero is **masked as unverified/possibly
  missing**, not labelled as proven missing. Include a
  secondary analysis that treats finite zeros as valid and
  clearly contrasts its outcome. Do not impute from future
  values in any analysis.
- Primary metric: **sensor-balanced MAE** (average per-sensor
  MAE across the same evaluated sensors; each sensor weighted
  equally, regardless of missingness). Report pooled MAE,
  per-sensor MAE distribution, RMSE, masking fractions and
  lambda for each horizon/model as secondary metrics.
- For G, P, S and G_perm calculate losses using the **same**
  sensor/horizon availability mask. Reject malformed results,
  empty denominators or missing primary outcomes.

## Fixed decision rule

Let `M_h` be the test MAE for model `M` at horizon `h`,
and `B_h=min(P_h,S_h)` select the stronger baseline on TEST
*only for reporting/comparison*, not for retuning G.
For every `h in {3,6,12}` require:

```text
(B_h - G_h)/B_h >= 0.01
(Gperm_h - G_h)/Gperm_h >= 0.01
```

If either denominator is nonpositive, stop as non-evaluable.
Do not retroactively remove a horizon, choose new lambdas or
change the 1% threshold after reading test errors.
A positive result requires all **six** inequalities. If
H1 fails, report a negative result, including whether G
underperformed, tied or selected lambda zero. A negative
result is an informative scientific result.

## Additional controls, uncertainty, and limitations

- Report a **fixed-lambda-zero** recovery check: G must equal
  persistence exactly. Evaluate invariance to simultaneous
  permutation of graph and sensor order in deterministic tests.
- Report a second, non-primary sensitivity analysis where zero
  speeds are valid finite observations. Reuse selected validation
  lambdas; no reranking on test.
- Report per-horizon unpooled sensor errors and signs of effect.
  A descriptive circular moving-block bootstrap of 7-day
  blocks over test days, 500 resamples and RNG seed 20261023
  may be reported, with explicit warning if the test interval
  offers too few independent weekly blocks; it is **not**
  part of the primary binary decision rule.
- DCRNN's published results are prior literature, not a
  reproducible control unless preprocessing, splits,
  training and computational budget have been independently
  matched. This lightweight G is not a fair claim to
  outperform the DCRNN deep-learning architecture.
- Directed road-distance weights are not a measured causal
  propagation matrix. Graph-model performance, positive or
  negative, cannot alone establish a physical perturbation
  response mechanism.

## Identification gate for the original scalar hypothesis

**RP-E002-G0 = NOT IDENTIFIED for METR-LA alone.**
The recorded sampling period does not measure response latency
`tau`; sensor count is not update capacity `B`; and traffic
variability is not uniquely measurement noise `I`.
No independent recovery labels are supplied. The expression
`C=B/(I*tau)` is NOT evaluated as an empirical hypothesis
in this protocol. If independently measured variables
become available, register a distinct future study and
do not describe it as a completion of A01.
