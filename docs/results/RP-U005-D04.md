## First observed CSV gate failure

The frozen instrument stopped at the header-delimiter probe for **both** ZIP sources:

| Source | First parser decision | Recorded error |
|---|---|---|
| `occ_2026` | `SOURCE_SCHEMA_REJECTED` | `INVALID_HEADER_QUOTING` |
| `int_2026` | `SOURCE_SCHEMA_REJECTED` | `INVALID_HEADER_QUOTING` |

The overall original decision was `SOURCE_GATE_NOT_PASSED`. **These are instrument-emitted classifications, not evidence that the publisher's files contain invalid CSV.**

Inspection of the *source code after the first result* identifies a plausible **specific implementation defect**: `choose_delimiter` applies Python's `csv.reader(strict=True)` to **both** `;` and `,`, and raises immediately if either candidate parser fails. But a valid semicolon-separated header with quoted fields, for example `"A";"B";"C"`, parses correctly with semicolon and raises `',' expected after '"'` when incorrectly tried as a comma-separated record. Thus an irrelevant candidate can veto an otherwise valid header. This failure mode can be demonstrated using artificial strings, without inspecting ANEEL original records.

**Inference limit:** The observed error string is *consistent* with this defect, but the original audit did not persist raw header bytes. We have not yet directly demonstrated that those two specific ANEEL headers use the quoted-semicolon structure, and must not assert it as verified. A separately registered, bounded diagnostic is required before attributing the actual first-run failure to this particular cause. Do not modify the original report or retrospectively declare its ZIP/CSV source gate passed.

The original script stopped before full CSV processing. Consequently **no full original decompressed CSV SHA-256, ZIP member CRC/EOF, source-header column list or total event-row count was established**. No claim of complete row coverage or any source join is allowed from this result.
