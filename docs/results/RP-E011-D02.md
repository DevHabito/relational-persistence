# RP-E011-D02 — Original JSSPP CERIT-SC source schema REJECTED

**First, permanent, preregistered verdict: `DATASET_SCHEMA_REJECTED`.**

The original downloaded file is REAL and independently
collected. However, the strict D02 source gate required
**zero** invalid job IDs, and the data contained **one**.
The previously registered decision is therefore
a **source-eligibility rejection**, not a prediction
result and not a declaration that every job record
is unusable. The original failure is preserved.

Every data row parsed into **22 documented fields**
after quote-aware tokenization (472,400 such rows).
There were **no header-comment lines** in the

`dd48cf7ca369d485b14add5d2baca70a1001c19d9b447688ff7639812673dc7c`

The exact direct `https://jsspp.org` URL and final
response URL matched. Although the server labeled
the transfer as `application/x-shockwave-flash`,
the downloaded **actual source bytes** were
valid UTF-8 extended SWF text. We did not
misclassify the data as binary Flash from
its MIME label.

The first-run source scan did **not** preserve
the exact row index or numeric value of
the anomalous job ID in its permanent metadata;
it recorded only the count, so we **cannot
truthfully identify the cause** from this audit.
Do not assert the row was a header, an ID zero,
a generated artifact, or some other explanation
without a separately labeled source-only
investigation.

## Why D02 did not pass, despite the substantial dataset

The scientific protocol registered the
conjunction of source eligibility gates
before reading the original job records.
Most gates passed, including genuine
extended queue-name coverage. One did not:
`invalid_job_id == 0`.

Changing the zero-tolerance ID condition
to "at most one" after the fact would be
a **post-hoc eligibility adjustment**.
We did not make that adjustment and
will not label this D02 outcome `PASS`.

A separately preregistered **source-only
anomaly investigation** could determine
the exact position and nature of that
record using the exact original SHA-256.
It would not rewrite this first-run
decision. Whether a different future
data-use protocol could explicitly
exclude that record without undermining
inference is a separate methodological
question to be justified and disclosed,
not assumed.

## Claims that remain unverified

No D02 predictor was implemented, trained
or scored. This report makes no claim that
a backlog trend beats historical baselines,
that external HPC queues behave like
single FIFO servers, or that any new
relational stability law exists. The
RP-E010-P01 49,995-case negative
forecasting result remains valid.
