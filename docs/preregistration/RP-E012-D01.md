## Frozen causal capability classification

Use TWO INDEPENDENT conservative parsers for the publisher
`.proto` file: (A) message/enum-block extraction by bounded
regular expressions and (B) a simple independent line/brace
scanner. They must agree on every required field and event.
A compiler is not needed to establish these specific names;
no protobuf decoding or source-row statistics are attempted.

Check exact message/field presence, never substituting
similarly named, non-equivalent fields:

- `InstanceEvent.time` and `type`,
  `collection_id`, `instance_index`,
  `machine_id`, `resource_request`,
  `priority`, `missing_type`.
- `CollectionEvent.time`, `type`, `priority`,
  `start_after_collection_ids`, `missing_type`.
- `MachineEvent.time`, `machine_id`, `type`,
  `capacity`.
- `InstanceUsage.start_time`, `end_time`,
  `average_usage`, `maximum_usage`,
  `assigned_memory`.
- `EventType.SUBMIT`, `SCHEDULE`,
  `EVICT`, `FINISH`, `UPDATE_PENDING`,
  `UPDATE_RUNNING`.
- `MissingType.SNAPSHOT_BUT_NO_TRANSITION`,
  `NO_SNAPSHOT_OR_TRANSITION`,
  `EXISTS_BUT_NO_CREATION`.

These fields support **potential event-time reconstruction**,
not verified raw-row coverage, actual resource occupation at
each origin or an actual start/completion identification.
`SCHEDULE` is a scheduler-placement event, not guaranteed
physical execution start. `InstanceUsage.end_time` is the
earliest declared conservative *observation-time release*
for that usage window: future-ending window aggregates
MUST NEVER enter an earlier prediction. `InstanceUsage.
assigned_memory` is a memory-limit feature, NOT an
enforced wallclock-run-time cap.

Hard elapsed-service expiry requires an explicit duration cap
field and verified enforcement/override policy. We will
search ALL publisher message fields for exact predefined
property-name patterns:
`time_limit`, `runtime_limit`, `walltime`,
`wall_time`, `max_runtime`, `max_duration`,
`duration_limit`, `hard_time_limit`,
`deadline`, `execution_timeout`,
`runtime_cap`. If absent, return the **narrow** conclusion
`NO_EXPLICIT_HARD_RUNTIME_CAP_FIELD_IN_PINNED_SCHEMA`;
do not claim the real provider has no such mechanism.
If present, do NOT conclude enforcement; report
`RUNTIME_CAP_FIELD_PRESENT_ENFORCEMENT_UNKNOWN`.
No inference from `assigned_memory`, `start_time`,
timestamps or CPU percentiles is permitted.

## Frozen outcomes

- `SCHEMA_EVENT_METADATA_PRESENT_RUNTIME_CAP_UNVERIFIED`
  iff original files pass Git blob checks; both independent
  parsers agree; all listed event fields/names and synthetic
  missing flags are present; and NO exact time-cap field
  is found. This says the SCHEMA can theoretically support
  cautious event reconstruction, but **does not** meet
  RP-F007's required enforced time-cap evidence.
- `SCHEMA_EVENT_METADATA_PRESENT_ENFORCEMENT_UNKNOWN`
  if the same event gates pass and a cap-named field
  exists. Even here, the cap's enforcement remains unknown;
  no RP-F007 empirical transfer claim.
- `SCHEMA_REQUIRED_EVENT_METADATA_MISSING` if original
  file verification passes and the independent field or
  enum gates agree on one or more missing required fields.
- `SCHEMA_SOURCE_ACCESS_BLOCKED` for unavailable official
  byte download; do not assert field absence.
- `SCHEMA_SOURCE_IDENTITY_MISMATCH` if pinned Git blobs
  fail identity (abort parsing).
- `SCHEMA_PARSER_DISAGREEMENT` if the two methods
  disagree about fields/events; do not reinterpret
  a stop as scientific evidence of absence.

Record exact version and stable identities, fields, named
events, limitations, no raw event counts, no forecast loss
or new Lean theorem. Save original first-run metadata as
an immutable GitHub Actions archive even for adverse outcomes.

## Required adversarial and negative controls

Tests on SYNTHETIC protobuf text must reject (without false pass):
missing SCHEDULE or UPDATE_RUNNING, absent timestamp,
changed field spelling, resource `assigned_memory`
relabeled as hard walltime, deliberately inserted hard runtime
cap (must yield ENFORCEMENT_UNKNOWN, never verified),
unknown missing-event flag, parser/encoding/identity mismatch,
and future usage windows with `end_time>origin`.
A correct event-time state extractor must treat events at
timestamp `t` as NOT previously observed at origin `t`,
under a strict `event_time < t` rule.

No extra external source is silently substituted. No
scheduling interventions, distributional claims, row-level
coverage rates, walltime guarantees, causal effect of
bounds, C formula validation or new queue theory.
Only a *schema + causality-guard* decision.
The original raw production data remain unexamined.
