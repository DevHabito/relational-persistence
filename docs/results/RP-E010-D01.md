# RP-E010-D01 — Third-party production workload trace audit

**Current state: preregistered, first original source audit not yet executed.**
No new real-world predictive outcome has been computed.

## What this phase actually tests

After the internally run software RP-E009 result, the
[RP-E010-D01 protocol](../preregistration/RP-E010-D01.md)
was frozen on `main` before source-byte retrieval or
modeling. It selects a third-party public HPC workload
with documented submission and wait timestamps for a
**source feasibility audit only**.

The HPC2N Seth cluster in Sweden is not our executable
service. Its workload logs were originally contributed by
HPC2N and curated by the Parallel Workloads Archive (PWA).
The cleaned trace omits substantial anomalous or
dominant-user activity by upstream rules, and its
sample selection is **not representative by default**.

We identify the exact mirror source by repository,
pinned commit, file path, expected size and expected
Git object hash. The first data-acquisition CI job
will retain SHA-256 and full field-quality/format
counts and compare them with an independently
implemented parser. It may classify the source as
`DATASET_SCHEMA_VERIFIED`, `DATASET_SCHEMA_REJECTED`,
or `SOURCE_ACCESS_BLOCKED`.

## Critical source exclusion

Do **not** use the original NASA-iPSC-1993 trace
as proof of measured job submission times.
Its original archive documentation explicitly
says submission times are unavailable and the SWF
conversion substituted job start times in their
place. Treating those values as true arrivals
would manufacture queueing data.

[HPC2N source notes](https://www.cs.huji.ac.il/labs/parallel/workload/l_hpc2n/),
[SWF field definitions](https://www.cs.huji.ac.il/labs/parallel/workload/swf.html),
and [NASA conversion caveat](https://www.cs.huji.ac.il/labs/parallel/workload/l_nasa_ipsc/).

## Deliberate limits

**This first D01 run computes no recovery
prediction, forecasting score, fitted parameters
or general relational-persistence statistic.**

Even if a cleaned, mirrored SWF passes schema checks,
the scheduler is multi-processor, not our
single-worker FIFO; job submissions, dispatch
decisions and wait times are observational and
may be confounded by workload sizes, priorities,
partitions, periodic changes and curation. A
new frozen prediction protocol must define those
variables and holdout boundaries *before*
scoring real HPC2N labels.

The mirrored GitHub file is version-pinned,
but the D01 protocol does **not** assert
identical bytes to the archive's independently
hosted compressed original. Full source bytes
are not rehosted in this repository.

The existing Lean 4 proofs are independent
of this data audit. Passing schema validation
does not prove any new mathematical or
physical claim.
