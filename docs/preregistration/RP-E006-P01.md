# RP-E006-P01 — Prospective held-out queue-recovery forecast test

**Frozen before implementing or running RP-E006 measurements.**
This is a **single-software-implementation, hosted-VM performance benchmark**,
not a physical-law test. It intentionally permits the scalar candidate
`C=B/(I*tau)` to fail against classical queue-state information.

## Question

Within the declared single-worker FIFO software service, can an
index-only fitted predictor using `1/C=(I*tau)/B` outperform BOTH
(i) a training-set constant and (ii) a fixed workload/throughput
queueing approximation for **future** recovery times, in a
forward-held-out block? Is there enough independent intervention
variation to make this restricted forecast question answerable?

Prior RP-E004/E005 results checked only instrument replay. They
did not test this question. All existing logs and first-run
archives remain immutable; they are never training examples here.

## Timing and separation

Two separate standard `ubuntu-24.04` GitHub-hosted VM jobs with
Python 3.12, using the same version-pinned source commit:

1. The **training job runs to completion first**. Only after
   it exits does the held-out test job start, on a fresh hosted
   VM. An additional evaluation job runs after both. The
   work is a single hosted software benchmark, NOT independent
   physical replication or population sampling.
2. Exactly **nine** intervention cells formed by the Cartesian
   product of accepted-work targets `N ∈ {60,100,140}` and
   scheduled controller application lags
   `d ∈ {0.015,0.070,0.120}` seconds after external
   injector onset. Every cell appears **twice in training**
   (18 sequential fresh-server trials) and **once held-out**
   (9 new sequential fresh-server trials). Each block's
   order is deterministically shuffled, train seed
   `20261026`, test seed `20261027`, independent of outcomes.
   Cell duplication is not a claim of i.i.d. sampling.
3. All trials have positive workloads and an enabled
   controller. `I=0` or missing controller action makes
   `C` undefined and lies **outside the registered forecast
   domain**, not a case to impute or silently exclude.
   P02/E005 negative controls already document that boundary.
   Fail to acquire **any** registered positive intervention
   or any valid finite recovery label => `STOP_INSTRUMENTATION`
   for the **entire** experiment, not selection of passing trials.
4. Disturbance is HTTP localhost task submissions paced by
   nominal `3 ms` each, in exactly the positive accepted count,
   against a fresh single-worker FIFO queue. The worker
   processes a fixed `12 ms` per task initially; the controller
   action changes subsequently started tasks to `6 ms`.
   Queue cap `512`. Keep the separate calibration/monitor
   process semantics from RP-E004-P02; no service instance
   re-use across trials.
5. The scheduled lag `d` is a treatment assignment only.
   `tau` is the **actual service-side application time minus
   independently timestamped injector onset**, observed on
   a common monotonic clock, never the scheduled value.
   Require `0<tau`, service action before injection end,
   send <= applied <= acknowledgment, valid fixed order
   and all 27 interventions accepted. A late or missing
   action STOPs the experiment.
6. Fix three **pretrial** saturated capacity windows (180
   calibration work units) and sparse contrasted calibration
   as in P02. `B` is their measured completed-work rate
   in task/s. `I=N / (end-onset)` in task/s. One-sided noise
   and exact machine timestamps are archived, with
   all original per-trial role and probe files retained.
7. The outcome `Y` is the first **sampled** queued=0 and
   active=0 after injector end, if followed by at least
   500 ms of sampled idle with no observed nonidle interval.
   Every sample is kept; gap limit 150 ms, followup up
   to 8 s. Y = (first-idle-sample - injector-end) seconds.
   Recovery is calculated from injector end marker and
   monitor samples **without using any predictor**, and
   independently cross-checked with a second group-based
   oracle. No assertion of continuity between samples.

## Forecast origin and allowed inputs

**Forecast origin is injector end**, before reading any
post-end sample (which might itself reveal recovery).

All allowed features existed at or before that instant:
pretrial B, accepted N, actual injector duration (for I),
actual service action latency tau, last externally sampled
status **at or before end** (queued+active), and action
change's prespecified twofold processing-rate multiplier.

The last pre-end sample must be present, ordered and no more
than 150 ms before injector end. Prohibit use of first
post-end status, recovery confirmation, measured post-end
work, future timestamps, or test-block outcomes in
forecast features or fitted parameters.

The candidate index `C=B/(I*tau)` has units s^-1
under the declared work/s conventions; its reciprocal
`Z=1/C` has seconds. C or Z is an *operational*
candidate, not a derived physical law.

## Frozen prediction rules

Fit **only on 18 training labels**:

- **Index-only primary:** ordinary least squares
  `Yhat_C=max(0,alpha_C+beta_C*Z)`,
  with exactly two fitted coefficients and intercept.
- **Constant baseline:** `Yhat_const=mean(Y_train)`.
- **Tau-only negative comparator (secondary):** ordinary
  least squares `max(0,alpha_tau+beta_tau*tau)`,
  train-only.
- **Workload-only negative comparator (secondary):**
  ordinary least squares
  `max(0,alpha_N+beta_N*N)`, train-only.
- **Queueing primary comparator:** fixed, **unfitted**
  fluid backlog approximation
  `Yhat_queue=max(0,(last_pre_end_queued+active)/(2*B))`.
  This is a simple work-conservation approximation for a
  single worker with nominally halved service time, NOT
  an application of Little's equilibrium law. Its
  expected failure under stale samples and host jitter
  does not make it a fitted baseline.
- No model sees `Y_test` during fitting. No weighting,
  per-cell parameters, robust fitting choice, model
  selection or hyperparameter tuning. Any zero training
  variance for Z, tau or N, invalid/NaN coefficients or
  missing feature => `STOP_MODEL_IDENTIFICATION`.
  Save fitted coefficients and individual predictions
  before releasing aggregate test metrics.

## Frozen decision and metrics

Primary metric: **MAE in seconds**, averaged once over
the nine held-out trials, computed for C, constant and
queue baseline from identical outcomes; MAE=0 is valid
for a baseline but cannot be used in an improvement ratio.

`PASS_PREDICTIVE_GAIN` iff all trials/invariants are valid,
both comparator MAEs are **strictly positive**, and

`MAE_C <= 0.90*MAE_const` **and**
`MAE_C <= 0.90*MAE_queue`.

Otherwise, if observations are valid, declare
`NO_REGISTERED_PREDICTIVE_GAIN` (including any zero
comparator MAE). If any data-quality, source-integrity,
pre-end feature, training fit or train/test separation
invariant fails, emit `STOP_INSTRUMENTATION` or
`STOP_MODEL_IDENTIFICATION`, not a substituted label
or tuned threshold.

Secondary: signed bias, cellwise absolute errors, tau-only
and N-only MAE, per-cell train/test observations, and
the recorded range of B,I,tau,Y and C; no inferential
p-value or population confidence interval, because
independent sampling and adequate power are not established.

A negative result is a legitimate primary outcome.
Train/test partition, cell grid, metric, threshold,
runtime, preprocessing and baseline were all specified
before the first E006 observation. Never rerun failed
jobs as if replacing the first trial set.

## Integrity and archival

- Every original trial stores calibrator, injector, controller
  and health JSON; append-only monitor samples and
  service-action events, and a pre-end predictor snapshot.
  The snapshot is a **feature-only** event and must have
  timestamp <= injector end; a cross-check with the original
  monitor stream prevents invented pre-end states.
- Original logs and run summaries are hashed; store job
  IDs, source SHA, frozen protocol SHA, platform/Python,
  actual execution order, and slot.
- The aggregate job **must use immutable artifact bytes**
  from both separate jobs, verify every expected path,
  time-order, treatment assignment, monotonic constraints
  and hashes, recompute all labels independently, then
  train/evaluate. Do not read handwritten summary target
  columns in place of raw observations.
- Archive **the first run** and its STOP/PASS verdict with
  original source logs permanently, or explicitly record
  failure if a trustworthy archive commit cannot be made.
  Failures and right-censored records are preserved.
  Never rewrite original RP-E005 measurements.

## Interpretation and prior work

Classical FIFO conservation and workload backlog models
must be treated as serious alternatives. This toy test
can reject the registered index-only forecast relative
to the declared baselines for this service and domain.
It cannot prove a new universal physical law even if PASS,
or logically falsify all conceivable operational definitions
of relational persistence if NO_GAIN.

Little (1961), "A Proof for the Queuing Formula: L=lambda W",
https://doi.org/10.1287/opre.9.3.383 is prior queueing
literature. Our simple finite-backlog/throughput
approximation is distinct from Little's stationary theorem.
For leakage-safe ordered train/test model evaluation,
see https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html.
No new Lean theorem is proposed by this hosted software
benchmark; established Lean CI remains a separate
regression check.
