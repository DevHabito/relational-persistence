D06 had already verified 6,789,484 occurrence rows and 6,078,331 interruption rows from two exact 2026 ANEEL publisher ZIPs, with complete source ZIP SHA-256 and CRC, semicolon-delimited UTF-8 CSV, 23 and 26 fields, and material missingness in the recorded emergency-response phase durations. That documentation justifies examining a *candidate textual linkage*. It does not justify inferring that real events match, that identifiers are unique, or that an algorithm chose any link repair. ## Frozen key and observations

The D07 key required four literal source strings: 14 ASCII decimal digits of distributor CNPJ; the literal year `2026`; a **two-character month `01` through `12`**; and 1–10 ASCII characters of occurrence ID without leading/trailing whitespace. No leading zeros, company scope or calendar boundaries were normalized to make more records match. Rows that failed any condition were **counted**, not silently removed from the source denominators.

The two exact original 2026 publisher sources were downloaded again in full. Both compressed original ZIP digests and both full decoded CSV SHA-256 digests matched D06, with full member read to EOF and ZIP CRC checked. There was no different source snapshot:

| Emergency occurrences | **6,789,484** | **0** | **6,789,484** |
| Electricity interruptions | **6,078,331** | **0** | **6,078,331** |

Every row failed D07's **strict two-character month rule**, as independently counted by the program for each exact publisher source. There were also **1,929,271** occurrence source rows and **1,293,508** interruption source rows with the original occurrence-code string failing D07's separate ASCII, 1–10 character, nonempty, non-whitespace-trim or reserved-separator conditions. These invalid-reason counts **overlap** and **cannot be summed**.

The distributor CNPJ format and literal competence-year test reported **zero invalid rows** in either source. These are syntactic checks only, not validated corporate identifiers or operational facts.

**Critical:** the original report does **not** contain a histogram or sample of what the actual month strings looked like. A plausible source-format hypothesis is an unpadded one-digit representation or another month encoding, but D07 did not test that. A high invalid rate under *our declared representation* does not establish a publisher data error. Similarly, the occurrence-code failures combine multiple reasons; none may be assigned a specific cause from these aggregates alone.

## Why the apparent zero join is scientifically undefined

Because D07's admissible key predicate accepted **no original row**, both temporary grouped key tables were empty. The SQL census correctly reported zero distinct valid keys, zero matched keys, zero unmatched valid keys and zero one-to-many groups. The source-accounting identities all passed: original rows = valid + invalid and grouped counts balanced.

It would be erroneous to conclude **0% of the real events match**, or that zero occurrences are related to real interruptions. The useful comparison population is empty. No conditional matching rate is defined from zero candidate keys. Even a later large textual match rate would require independent semantic and temporal checks before it could be considered an actual event-linkage rate.

Our initial key rule was more restrictive than the file representation supports. The failure is a clear constraint on the **research instrument**, not a new finding about physical network persistence.

## Source limitations, controls and next separate task

This run **cannot** establish any source crosswalk success, mismatch, uniqueness, chronology, record completeness, assignment of repairs, actual recovery times conditional on real operator decisions or effect of a lookahead policy. It is also silent on the applicability of a two-vertex-disjoint path F2 metric to commonly radially operated electricity distribution feeders.

The next *separate* task, RP-U005-D08, should freeze a **low-cardinality lexical format audit**, not a new join. It may count original month string lengths and value frequencies in an allowlisted **month domain** (and format-failure categories for occurrence-code fields), conditional on reobtaining the **same exact two original ZIP SHA-256s** and revalidating their complete decoded bytes/CRC. No original CNPJ or occurrence-code value should be recorded or published. That subsequent result might support a new, explicitly registered D09 key-census representation, but **must not alter D07's original negative key decision**.

The phrase `BOTH_SOURCE_KEY_CENSUS_AUDITED` in the original program means *the prescribed computation completed*, not that there were eligible keys or that the two tables were linked meaningfully. This distinction belongs in the claim ledger.

**Conclusion:** **0/12,867,815** original rows were admissible under the frozen D07 literal key. No empirical event match rate exists under that key; the data-format hypothesis remains to be tested independently. No new mathematical law or repair-policy evidence follows.
