# RP-E007-P01 — Prospectively fixed two-sample backlog forecasting

**Measurement status: NOT YET COLLECTED.**

This scientific report is created **before** the new hosted
instrumentation run. Neither the earlier RP-E006 source
archive nor synthetic regression fixtures are acceptable
as prospective observations for RP-E007.

## Frozen hypothesis and existing literature

[RP-E007-P01 preregistration](../preregistration/RP-E007-P01.md),
committed to `main` before implementation at `150dd5f`,
defines the entire treatment grid, reuse of the unchanged
RP-E006 collection instrument (but **new** trials),
two fixed forecasts, feature cutoff, primary error,
success threshold and STOP rules.

The question is whether using a **second pre-end queue
observation** improves a classical backlog/throughput
recovery forecast. This is a standard time-dependent
queue-estimation idea, not a physical or mathematical
novelty claim. Refer to Ross, Taimre and Pollett (2007),
[Estimation for queues from queue length data](https://doi.org/10.1007/s11134-006-9009-2).

## Frozen prospective study

18 fresh-software-service training/diagnostic trials
will precede nine new held-out trials on a different
GitHub-hosted VM job. Both blocks cover all nine
accepted work-size / scheduled-action-delay cells
`N∈{60,100,140}`, `lag∈{15,70,120} ms`.
The existing `rp_e006_acquire.py` code provides
identically defined calibration B, service-applied
action times, injection-end markers, raw monitor
probes, sampled recovery Y and 8 original logs
per trial. Its *original RP-E006 schema label*
remains in the new source records, not falsified as
a different instrument.

At injector end, using the **two most recent earlier
or simultaneous** samples of queued+active work:

```text
q_prev = queued_prev + active_prev
q_last = queued_last + active_last
v = (q_last-q_prev) / (t_last-t_prev)
h = injection_end-t_last
q_extrapolated = max(0, q_last + v*h)

STATIC: Yhat_static = max(0, q_last/(2*B))
TREND:  Yhat_trend  = max(0, q_extrapolated/(2*B))
```

No feature can depend on a post-end observation,
observed recovery or trial-result metric. Both
predictors use **identical pretrial B**. The
two-sample slope has no fitted coefficient or
smoothing choice.

On the nine independently held-out outcomes,
**`PASS_TREND_INCREMENT` requires at least 10%
less MAE for TREND than STATIC**, provided STATIC
MAE is positive. Otherwise classify valid data as
`NO_REGISTERED_TREND_GAIN`. An invalid probe gap,
missing original record, contaminated input or
invalid recovery produces `STOP_INSTRUMENTATION`.

The training average is recorded as a **secondary**
benchmark and is computed from 18 new training
labels only; the trend and static primary models
are completely unfitted.

## Scientific boundaries

A PASS could support prospective **classical online
queue-state forecasting** in this specific software
system. It would neither validate a physical
relational-persistence law nor demonstrate novelty.
A NO_GAIN would mean the fixed slope correction
failed its registered threshold, without ruling out
other estimators. Generalization to different
systems and true physical measurements remains open.

Existing Lean 4 theorems are checked for regression
only; RP-E007 introduces no mathematical theorem
that should be misrepresented as a physics proof.
