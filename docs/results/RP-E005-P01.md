# RP-E005-P01 — Two hosted-runner measurement replication

**Execution status: NOT YET MEASURED.** This page was prepared before
running the new experiment. Do not interpret its existence, a passing
code regression, or a preregistered hypothesis as observed success.

## What will count as an observation

The first `main`-branch execution of
[the frozen RP-E005-P01 workflow](../../.github/workflows/rp-e005-p01.yml)
will provision two separately hosted Ubuntu VM jobs and preserve
their four RP-E004-P02 software trials each. A third job independently
replays all archived health samples, controller application records,
saturation-calibration windows and injection end markers, and
recalculates all per-trial evidence and file hashes.

Primary verdict is either:

- `PASS_TWO_RUNNER_REPLAY`: eight replayable P02 trials from two
  distinct hosted job slots and all 48 role/trace files verify.
- `STOP_REPLICATION_AUDIT`: **anything else**. Raw observed bytes
  and reasons must be preserved rather than inventing a passing run.

A successful outcome would be **instrument replayability on two
separately hosted software environments**, not independent physical
instruments, statistical causal inference, a field observation of
persistence, or validation of `B/(I*tau)`.

## Post-run reporting obligations

Record the *actual* first workflow run ID, both job IDs and statuses,
first archive commit or evidence of archival failure, original source
SHA and protocol hashes, the two actual `P02` decisions, the
48 verified source hashes, audit failure reasons if any, and the
four controlled-positive `B`, `I`, `tau`, `Y` values in
their declared units. Preserve all right-censored or failed cases.
Do not select a better-looking run to replace the first one.

No Lean theorem is introduced by this experiment. The previous
Lean verification remains a separate mathematical checkpoint.
