# RP-E009-P01 — Prospective executable-service transfer

**Status: NO RP-E009 EXPERIMENTAL OUTCOME COLLECTED.**

## Scientific design

[RP-E009-P01 protocol](../preregistration/RP-E009-P01.md) was
committed to `main` at `61674d0` before the independent
asyncio TCP server and its client/auditor were implemented.

The original RP-E006/007 service uses a different HTTP
threaded execution path. RP-E009 runs its own TCP JSON-line
server in a separate OS process, an `asyncio.Queue` FIFO,
and an event-loop worker with service-side accept/start/complete
logging and real monotonic-clock observation. The new
implementation does **not import** the earlier server.
It is nevertheless a localhost Python service on
GitHub's hosted Linux platform, so no independence
of hardware or external real-world transfer is implied.

Nine diagnostic trials and nine **future held-out** trials
on separately provisioned Ubuntu hosted VMs use the
predeclared cross product of N={40,70,100} and
arrival patterns {uniform, early_burst, late_burst}.
Every trial calibrates B on 60 prechange tasks,
applies a separately timestamped factor-two service
speed change before workload injection, and archives
actual request/acknowledgment timestamps and
complete service-side events and sampled health states.

## Frozen forecasts and decision

Only the two most recent original status samples no
later than client-side end of injection are allowed.

```text
q = queued + active
STATIC = q_last/(2B)
TREND = max(0,q_last + (q_last-q_prev)
             * (end-t_last)/(t_last-t_prev)) / (2B)
```

Both are unfitted. The first sampled recovery status
with 500 ms of confirmed sampled inactivity is the
outcome. It is computed without any predictor and
checked by two independent recovery algorithms.

The preregistered primary comparison is **MAE over
nine new held-out trials**. The TREND model passes
only at >=10% improvement over static; a valid
lesser result is `NO_REGISTERED_EXECUTABLE_GAIN`.
Any invalid original events, late status, changed
SHA256, missing or censored case yields
`STOP_TRANSFER_AUDIT`, never selective dropping.

## Integrity obligations after running

The first hosted workflow must preserve the
18 individual first-run source records, 126
original per-trial role/event files, original
train/test provenance and summaries, and
the evaluator's source-only decision. The
entire archived file set receives SHA-256 digests.
An additional permanent regression must
replay every service event/monitor sample
and reproduce the first verdict from raw bytes
without executing new interventions.

Report full nine-case forecast errors and
MAE, each arrival pattern's errors, original
source and run IDs, failure reasons if any,
the saved archive commit, and limitations.

## Interpretation and prior work

A positive result would be a **limited transfer
of classical temporal queue forecasting**
between two different software implementations,
not a novel relational persistence law.
A negative result would be important evidence
that the improvement is contingent on the
original service or observation regime.
Neither would validate the original scalar
`C=B/(I*tau)`.

Async TCP servers and FIFO async queues are standard
Python primitives:
https://docs.python.org/3/library/asyncio-stream.html
https://docs.python.org/3/library/asyncio-queue.html

The approved Lean 4 theorems remain separate
exact mathematical statements; this study
introduces no new theorem.
