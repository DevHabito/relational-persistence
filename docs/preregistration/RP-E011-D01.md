# RP-E011-D01 — Frozen official Polaris scheduler source feasibility gate

**Registration occurs before RP-E011 code, first official source retrieval
or any external Polaris outcome/feature inspection.** This D01 phase is
strictly about SOURCE ACCESS, provenance, field semantics and data quality,
NOT prediction, discovery or a new Lean theorem.

## Motivation and independently published primary source

RP-E010-P01's 49,995 held-out historical HPC2N task waits yielded the
frozen negative decision `NO_REGISTERED_OBSERVATIONAL_GAIN`, with
a two-snapshot waiting-job trend losing to two classical comparators.
That trace was upstream cleaned, all per-queue IDs were absent, and
the scheduler handled heterogeneous parallel resources. These
observations are frozen historical development evidence and cannot
become a second untouched holdout.

The new primary source is an **official DOE Argonne Leadership Computing
Facility (ALCF)** Polaris operational scheduler job export, not the prior
PWA HPC2N mirror and not our own synthetic/hosted service:

- Official catalog: https://reports.alcf.anl.gov/data/polaris.html
- Specific record:
  https://reports.alcf.anl.gov/data/ANL-ALCF-DJC-POLARIS_20220809_20221231.html
- Official field dictionary:
  https://reports.alcf.anl.gov/data/datadictionary/datadictionary_dim_job_composite.html
- Dataset type: `DIM_JOB_COMPOSITE`; machine: `Polaris`;
  exported CSV title `ANL-ALCF-DJC-POLARIS_20220809_20221231.csv`.
- Data interval: 2022-08-09 through 2022-12-31.
- Catalog **original CSV length 27,825,794 bytes**;
  indicated compressed length **2,261,468 bytes**.
- Catalog reports page last updated **2026-01-14**.
- This source is **not checksum/version pinned** by the upstream
  catalog. DO NOT pretend it is immutable. The FIRST retrieved
  source must have its exact SHA-256, compressed and uncompressed
  lengths, response headers, final download URL, retrieval date
  and original GitHub run ID archived before any forecast.

ALCF's official metadata distinguishes `QUEUED_TIMESTAMP` (when a
job entered a machine queue), `START_TIMESTAMP`,
`END_TIMESTAMP`, `QUEUE_NAME`, `NODES_REQUESTED`,
`NODES_USED`, `WALLTIME_SECONDS`, `QUEUED_WAIT_SECONDS`
(including ineligible/held periods) and `ELIGIBLE_WAIT_SECONDS`
(which excludes holds). These are source-documented columns,
NOT yet independently confirmed as populated for this exact file.
Do not treat the two wait columns as synonyms.
`NODES_USED` is known after allocation and is NEVER an
ex-ante allocation-request feature for later forecasts.
`EXIT_CODE` and other post-execution fields are also forbidden
from ex-ante prediction features.

Cite the original provider exactly in any derived publication:

"This data was generated from resources of the Argonne Leadership
Computing Facility, which is a DOE Office of Science User Facility
supported under Contract DE-AC02-06CH11357."

## Frozen acquisition, no silent substitute

The only allowed retrieval path is from the *specific official
resource page above*, using an HTTPS host belonging to
`reports.alcf.anl.gov` and a referenced link/button or a clearly
documented download action found on that page, requesting the
resource's **exact 20220809_20221231 Polaris filename**.

A source resolver may inspect the HTML document and associated
same-site forms/scripts for the download link, but it MUST
record the resolution method, all attempts, HTTP status
and selected exact URL. It must not search another mirror,
use a different year, rely on a guessed unchecked URL,
fabricate a checksum, silently log into third-party services,
or use later Polaris job exports.

If no stable trustworthy same-site resource download action
can be derived, report `SOURCE_ACCESS_BLOCKED`; do not
substitute one of the attractive but unverified links.
The first CI attempt is evidence even when blocked.

If compressed, use standard gzip decompression;
archive both downloaded compressed bytes SHA-256
and parsed original CSV SHA-256, when available.
The canonical CSV must have **exactly 27,825,794 bytes**
matching the official snapshot catalog for
`DATASET_SCHEMA_VERIFIED`; mismatched length
means `DATASET_SCHEMA_REJECTED`, with original
bytes still available only in the temporary
Actions artifact (subject to source-use terms).

## Frozen schema-only checks

Before inspecting the new source's numerical targets or
building predictors, require CSV header columns:

`COBALT_JOBID, MACHINE_NAME, QUEUED_TIMESTAMP,
START_TIMESTAMP, END_TIMESTAMP, QUEUE_NAME,
NODES_REQUESTED, NODES_USED, WALLTIME_SECONDS,
QUEUED_WAIT_SECONDS, ELIGIBLE_WAIT_SECONDS,
DATA_LOAD_STATUS`.

Interpret timestamps with `datetime.fromisoformat`
only when the original source follows its documented
YYYY-MM-DD HH:MM:SS[.fraction] format.
Preserve explicit timezone/no-timezone status;
do not silently reinterpret timezone.
Use standard `csv.DictReader` and a distinct
`csv.reader` row-width/count auditor on the
SAME original bytes; both must agree exactly on
row count and bad-width count. Require unique,
nonempty nonnegative numeric job IDs in the
identified corpus; report duplicates before
deciding the gate.

Count missing values for each required column
(no filling or per-queue imputation); count
records with usable submit/start timestamps,
nonnegative ordering, positive requested nodes
and a nonempty queue identifier.
Count **distinct observed nonempty QUEUE_NAMEs**,
but this is a SOURCE AVAILABILITY check,
not a forecast or model tuning.
For durations, count missing, nonfinite or
negative values separately, and compare
the documented queued-wait number against
(start minus queued) where both exist.
Do not use the disagreement to redefine
the primary observational target at D01.

Count missing `DATA_LOAD_STATUS`, successful
or other raw values; do not retrospectively
choose status filters after seeing wait errors.
Do not evaluate wait-time distributions,
quantiles, conditional means, feature correlations,
forecasting errors, or a target split in D01.

## Precommitted source eligibility gate

- `DATASET_SCHEMA_VERIFIED` iff a source is
  retrieved from the verified official resource,
  original CSV length equals 27,825,794 bytes,
  both independent CSV readers agree on record
  count and width, **no** non-header rows have
  incorrect widths, every populated job ID
  is well-formed and unique, at least **1,000**
  records have valid queued/start timestamps,
  positive requested nodes and nonempty queue,
  and at least **two** distinct such queue names
  appear in eligible records.
- `DATASET_SCHEMA_REJECTED` when an official
  download is obtained but one of the structural
  gates is not met. Report all observed problems.
- `SOURCE_ACCESS_BLOCKED` when acquisition
  cannot retrieve a confidently resolved
  same-origin source. If server times out,
  redirects outside the allowed host or
  offers an ambiguous button, preserve the
  failure rather than inventing the CSV.

This exact gate is frozen before first source
inspection. Structural failure does not authorize
different data, new filters, modified criteria
or a second original run.

The permanent repository archive should contain
only the complete **first-run audit JSON**, a SHA
manifest, original provider citation, chosen
download metadata and a full error report.
Do **not** add third-party bulk job records,
user names or project IDs to the repository.

## Interpretation and next research experiment

If D01 passes, a **separate prospective
prediction protocol** must be committed to
main before any forecasting is attempted.
It must explicitly distinguish
`ELIGIBLE_WAIT_SECONDS` from held/queued
wait, use timestamps available before the
job's submission, account for
`QUEUE_NAME`, requested nodes and
historical scheduler resource pressure,
and compare with strong classical
per-queue historical-wait baselines.
Any future holdout must be truly new for
these models and must not reuse the
RP-E010-P01 holdout as a blind test.

Do not claim physical law validation.
The original RP-E006 scalar result
remains negative. RP-E010-P01 remains
a negative observational forecast.
No new Lean proof is proposed for this
source-eligibility study.
