## Why the question was necessary

The original D07 study had completed exactly as its code specified but identified **no admissible cross-source candidate keys**. Every row in both fully authenticated 2026 original CSV snapshots failed its strict month predicate, which demanded two characters from `01` through `12`. The study also reported 1,929,271 occurrence rows and 1,293,508 interruption rows failing an independently specified **compound** occurrence-code syntax predicate. Neither outcome established that the regulator's data were corrupt or that no real-world incidents corresponded.

The present D08 audit was designed **after observing those D07 outcomes**. It registered in advance of *D08's* original source inspection exactly which benign month spellings it would report and which nonidentifying incident-code failure categories it would count. It does **not** retroactively repair D07's denominator, and should not be mistaken for a new blind prediction about restoration or a universal law.

## Exact observed month spellings

In both original CSVs, **all month field values were ASCII decimal strings without a leading zero**, as recorded in the first source JSON:

| Exact original month string | Occurrence rows | Interruption rows |
|---|---:|---:|
| `1` | 1,205,480 | 1,518,986 |
| `2` | 1,005,242 | 850,414 |
| `3` | 1,018,762 | 814,200 |
| `4` | 916,999 | 742,043 |
| `5` | 917,084 | 718,893 |
| `6` | 801,450 | 693,681 |
| `7` | 924,048 | 740,114 |
| `8` | 419 | 0 |

Month strings `9` through `12`, every zero-padded `01` through `09`, empty month and all other predefined residual lexical categories had **zero** records in these exact source files. All counts sum exactly to each first-run source total.

**This identifies the direct cause of D07's all-rows month ineligibility**: the original CSV representation uses unpadded month values (`1` not `01`). A dictionary's `Caractere(2)` field width does not imply that every published source value is left-zero-padded to two characters. The D07 rule was a **research specification error**, not evidence that source month fields are unusable. That original D07 decision and test remain preserved and unmodified.

These counts describe **the specific source versions** (as published and SHA-frozen), not the complete 2026 calendar or all electricity interruptions nationwide. The difference between 419 month-`8` occurrence records and no month-`8` interruption records does **not** establish a physical outage pattern; it could reflect publication cutoffs, source coverage, reporting lags or different inclusion rules. Those possibilities were not examined by D08.

## Separate occurrence-code syntax failure

D08's nonexclusive failure categories were:
- empty literal original occurrence-code field;
- length greater than ten characters;
- any non-ASCII character;
- leading/trailing whitespace;
- reserved internal separator U+001F.

After complete original source reads, **every** D07 compound code-syntax rejection was traced to exactly one observed failure category:

| Category | Emergency occurrences | Interruptions |
|---|---:|---:|
| Literal code longer than **10 characters** | **1,929,271** | **1,293,508** |
| Empty code | 0 | 0 |
| Non-ASCII code | 0 | 0 |
| Leading/trailing whitespace | 0 | 0 |
| Reserved separator | 0 | 0 |
| Original source rows passing the D07 code syntax | **4,860,213** | **4,784,823** |

The sum of the measured compound-code rejection rows **exactly equals** the first D07 failure totals, a frozen positive consistency check. Neither study exposed actual code values or identified the maximum length of any original code.

The authenticated 2026 dictionaries describe the corresponding occurrence code as a 10-character field, yet these exact original source CSV snapshots contain many longer strings. That is a documented **source-dictionary versus observed-field-width discrepancy**. It should be reviewed with the issuer's publication rules or a separate, safely aggregated length audit, **not** silently fixed by trimming identifiers, assuming the data are false, or declaring those records legitimate semantically based only on length.

## Scientific status and next gate

We now know **precisely** why the two D07 syntactic conditions rejected so many original rows: month strings are not zero-padded, and a substantial minority of occurrence codes exceed the fixed ten-character width. This answers a **data-format question**, not an event-linkage or system-restoration question.

A future **separately frozen D09** candidate-key study can use only mappings established from this format evidence, preserving the original unmodified month strings rather than guessing about numeric coercions. It must define **in advance** how to handle long occurrence codes, ideally reporting explicit parallel conventions (documented 1–10 character codes versus full bounded original strings) rather than selecting whichever gives the most favorable match count. It must also report duplicate, unmatched and one-to-many rows, and eventually validate temporal and feeder consistency in a *later* gate.

No D08 original rows were joined. No historically observable switching decisions, operator decision CPU costs, complete year population, two-path F2 energization state, causal greedy/lookahead benefit or pregeometry law was tested.

**Conclusion:** original 2026 source formats are now authenticated at a finer level, with a reproducible explanation for the D07 research-key failure. The original D07 result remains a valid record of that *failed key specification*, not a claim about physical events.
