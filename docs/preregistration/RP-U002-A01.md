# RP-U002-A01 — Preregistered finite component-turnover and relational repair

**Freeze this file ALONE on main BEFORE any RP-U002 source implementation,
numeric simulation, test fixture, or original run.** This is a separate
synthetic experiment. It neither alters RP-U001 first-run evidence
nor claims biological Amazon succession.

## Question, scope and prior literature

Does restoring the number of system components automatically restore
a prespecified FUNCTION when their relationships have not yet been
rebuilt? Does incremental repair restore that function at a cost in
discrete time? If two systems initially share six vertices, seven
edges and source/target degrees, can their exact time-integrated
function continuity differ during the same replacement schedule?

Prior theory includes Menger's theorem on vertex-disjoint graph
paths, network reliability and fault tolerance, graph repair,
C. S. Holling (1973) ecological resilience, and Gao et al.
(2016) network resilience. The exact experiment is a constructed
finite illustration of known graph principles, NOT a novelty
claim. Source component turnover is a toy abstraction with
zero ecology/clinical/network field observations.

## Original source graphs, protected terminals and fixed failures

Reuse the two original immutable RP-U001 graph edge lists
WITHOUT changing them:

A = {(0,1),(1,2),(2,5),(0,3),(3,4),(4,5),(1,3)};
B = {(0,1),(0,3),(1,2),(3,2),(2,5),(2,4),(4,5)}.

Undirected, simple, unit/unweighted edges. Source 0 and target 5
are always protected and never fail. For each graph test ALL
four distinct original internal component losses v in {1,2,3,4},
one at a time. Different scenarios reset to the original
full graph at t=0: NO accumulated multiple failures.

Time t is discrete 0,1,2,3,4,5.
t=0: original complete six-node source.
t=1: delete v and ALL of v's incident edges, no replacement.
t=2: introduce a distinct NEW component with ID (6+v);
      original v NEVER returns. Connect the replacement to
      exactly the FIRST old neighbor of v (ascending numeric order)
      with one undirected new edge.
t=3: attach replacement to the SECOND old neighbor, if any.
t=4: attach replacement to the THIRD old neighbor, if any.
t=5: attach replacement to the FOURTH old neighbor, if any.
No other edges change, no other component fails and no future
observations/target outcomes determine the precommitted order.
Every original internal vertex has at least 2 neighbors.
Each time step t>=2 permits at most ONE new edge.
The whole original topology is an assumed publicly known
repair blueprint. This is not an efficient or learned recovery
controller; it uses no future measurement, search-based
selection or fitted parameters.

A separate NO-REPAIR control deletes the same v at t=1 and
never replaces it or any edge through t=5.
Both policies experience exactly the SAME fixed v loss;
they have different component counts after t=2, so the
policy comparison does NOT pretend to match repair costs.
The replacement adds one new node and up to four new links
only to neighbors of the failed original, respecting
historical original adjacency.

## Operational functions and exact registered predictions

Let F1(G_t)=1 iff there exists at least ONE undirected
source 0 to target 5 path, and F2(G_t)=1 iff there exist
at least TWO internally vertex-disjoint simple source-to-target
paths. Both are evaluated at EACH time t, without averaging
across nonexchangeable domains or real populations.
Use BOTH oracle A (independent BFS reachability) and
oracle B (recursive enumeration of ALL simple 0->5 paths)
for F1, exact case-by-case. For F2 use independently
enumerated path interior disjointness and (for cross-check)
a separate independent vertex-removal test:
F2 iff F1 and after deleting EVERY ONE nonterminal
present vertex, F1 is still true (for these graphs;
Menger's theorem is known prior work).

Registered F1 positive counts out of EXACTLY four distinct
original single-failure scenarios per graph, at t=0..5:

- REPAIR A: [4,4,4,4,4,4].
- REPAIR B: [4,3,3,3,4,4].
- NO-REPAIR A: [4,4,4,4,4,4].
- NO-REPAIR B: [4,3,3,3,3,3].

The B node-2 scenario is the ONLY loss that interrupts F1.
Replacing the sixth node at t=2 does NOT restore its lost
function; adding its first, second and third old-neighbor
links restores reachability only at t=4. At t>=2 the
component-count after replacement is 6, identical to
the t=0 baseline, but F1 may remain zero.
Any discrepancy => REGISTERED_MODEL_PREDICTION_FAILED.

Registered secondary F2 positive case-counts at t=0..5:

- REPAIR A: [4,0,0,3,4,4].
- REPAIR B: [0,0,0,0,0,0].
- NO-REPAIR A: [4,0,0,0,0,0].
- NO-REPAIR B: [0,0,0,0,0,0].

The A node-3 scenario is the only single-loss scenario
that still lacks F2 at t=3; ALL repaired A scenarios
restore F2 by t=4. The stronger function therefore
has a different time of recovery than simple reachability.
At t=0 graph A has two independent paths, B does not.
These are PREDECLARED source topologies, not universal laws.

Uptime counts (the exact sum over 4 scenarios × t=1..5,
20 scenario-step observations, NOT population statistics):

- F1: REPAIR A 20/20, NO-REPAIR A 20/20;
      REPAIR B 17/20, NO-REPAIR B 15/20.
- F2: REPAIR A 11/20, NO-REPAIR A 0/20;
      REPAIR B 0/20, NO-REPAIR B 0/20.

No probabilistic random selection or significance interval.
This experiment records ANY negative differences:
repair improves B F1 uptime by only 2/20, NOT A F1;
and never establishes B's F2 function from nothing.

## Model validity and adversarial gates

- Confirm t=0 source topology matches the exact registered
  RP-U001-A01 original source graph and first-run hashes
  are never mutated.
- For EVERY graph and failed vertex and time, check original
  vertex v absent and replacement 6+v present iff t>=2,
  all edges physically attached to currently present
  vertices, all other original edges preserved, no
  replacement-neighbor edge not in v's old neighborhood,
  no extra edge, one new link each step until exhausted,
  no link between an absent node and another node.
- Replacement ID MUST differ from old ID and all old IDs;
  this models identity turnover, NOT the return of the
  original component.
- An independent event-replay state constructor and a
  separate closed-form original-edge-filter + repaired
  neighbor-set constructor must agree on exact present
  vertex and edge sets at every snapshot.
- F1 BFS and DFS must agree at each snapshot; F2
  path-interior disjointness and one-vertex-removal
  characterization must agree; F2 always implies F1.
- Exact baseline and recovery predictions above, no
  model retuning or favourable case selection.
- Independent "replacement-count only" counterexample:
  B, original v=2, t=2 has SAME total vertex count
  as t=0, but F1(t=2) is false whereas F1(t=0) true;
  its t=4 state has same vertex count but F1 is true.
- Negative controls: A F1 gains NOTHING from repair,
  B F2 gains NOTHING, no-repair B stays disrupted for
  five ticks in node-2 scenario.
- Finite Lean 4 theorem checks B node-2 replacement
  repair states at t=1..5 for F1 with exact fixed
  source edges and replacement-neighbor schedule.
  This is a kernel-checked Boolean finite certificate,
  not a full proof of the Python simulator semantics
  or all F2 cases or an ecological law.
- Python 3.11/3.12 regressions and Lean 4 on the exact
  PR reviewed head BEFORE first original GitHub experiment.
