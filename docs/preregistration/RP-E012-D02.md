# RP-E012-D02 — Frozen bounded original Borg event-prefix audit

**FROZEN BEFORE NEW RP-E012-D02 SOURCE METADATA OR ROW RETRIEVAL,
IMPLEMENTATION OR FIRST EXECUTION.** The fixed-source decision is
informed by Google public documentation; it is NOT blind discovery.

## Motive, source and registered objective

RP-E012-D01 already verified the pinned Google cluster-data v3 protobuf
event fields and missing-event flags (first source run #40234431456,
first archival commit `e68202a`), but read **ZERO original production
event records** and did NOT find a declared enforced wallclock
runtime-cap field. Do not rewrite this finding or claim RP-F007
synthetic hard service caps transfer to actual Borg scheduling.

The Google publisher's Aug 10, 2020 official announcement
https://groups.google.com/g/googleclusterdata-discuss/c/WuRDhbI8YzA
states that 2019 Borg cells are available as compressed JSON
objects in publicly named GCS buckets
`clusterdata_2019_${CELL}`, separated into
`machine_events`, `instance_events`,
`collection_events`, `machine_attributes` and
`instance_usage`. Original README may still say
BigQuery-only; do NOT purchase BigQuery queries.
The original Google academic dataset and trace/schema
are PRIOR literature, not project discoveries.

Question: can a zero-auth, zero-BigQuery-cost bounded HTTP
sample from TWO original provider event types be independently
authenticated at the object-generation level, decoded, and
checked for basic event-time/missingness semantics, without
leaking heldout labels, personal identifiers, or claiming
complete scheduler state?

## Frozen source, sampling and network budget

Exactly cell `a`, bucket `clusterdata_2019_a`.
Exactly two independent tables in this fixed order:
`machine_events`, then `instance_events`.

For each table, call Google's standard anonymous storage
JSON metadata/list endpoint under HTTPS host
`storage.googleapis.com`, bucket
`clusterdata_2019_a`, prefix `${table}-`,
`maxResults=100`; request a narrow field mask returning
object `name`, `size`, `generation`,
`md5Hash`, `crc32c` and the possible
`nextPageToken`. Do not paginate, use alternative bucket
names, or substitute mirrors. Sort the returned names
lexicographically and select ONLY the first whose filename
matches exact pattern
`^${table}-[0-9]+\\.json\\.(?:gzip|gz)$`.
If 100 metadata results contain no matching object (even
if another page might), stop as `SOURCE_ACCESS_OR_LISTING_BLOCKED`.
If the publisher returns HTTP 403/requester-pays,
stop without credentials, user-project billing or retry.

Record GCS generation, advertised original full byte size,
whole-object hash claims as metadata (if present), exact
selected name and HTTP result. A later object-generation
change is an identity failure; do not quietly select a
different shard. DO NOT claim a complete object SHA if
reading only its compressed prefix.

For each of the two selected original objects, request
`Range: bytes=0-2097151` against the official anonymous
storage JSON API `alt=media&generation=<pinned generation>`
using HTTPS; redirects only within
`storage.googleapis.com`; no credentials/cookies.
The process MUST NEVER read more than **2,097,152
compressed bytes per object** (4,194,304 across two
objects), **4,194,304 uncompressed bytes per table**,
and **500 complete JSON lines per table**. Read in bounded
chunks; ignore incomplete trailing JSON line, and record
its existence. Stop if decompression exceeds the declared
cap or a ZIP/bomb/truncated header prevents safe parsing.
If a server returns HTTP 200 instead of 206, still read
no more than the cap and explicitly record that partial
range semantics were not honored; do not claim complete
or byte-range authenticated data.

Use `gzip`-compatible incremental decoding through
`zlib.decompressobj(wbits=16+MAX_WBITS)`, strict UTF-8,
strict JSON (reject NaN/Infinity). Early cutoff means gzip
CRC/trailer may not have been read or verified; disclose.
Original media response bytes are NEVER committed to Git
and are discarded after report metadata are recorded.
No third-party IDs, obfuscated user strings, machine labels,
file content, or per-event rows may be committed.

Unchanged fixed selection regardless of outcome, prevalence
of missing flags, or number of valid rows. No random sampling,
time-range rebalancing or model fitting. This is an intentionally
nonrepresentative earliest-file / prefix sample.

## Registered independent row checks and observability gates

Two independent readers for each COMPLETE prefix line:
(A) standard `json.loads` with strict numeric handling;
(B) a separate field/value and shape validator over the
already split line; cross-check canonical integer event
times, event types and required IDs. They must agree.
Time and identities are JSON-decimal **strings** (per
publisher); reject time that cannot be converted losslessly
to an unsigned integer. `type` is likewise numeric string.
All records must be mappings, not arrays.

`machine_events` keys: mandatory `time`,
`machine_id`, `type`; event type in {1,2,3}
(add/remove/update); `capacity` optional.

`instance_events` keys: mandatory `time`,
`collection_id`, `instance_index`,
`type`; event type in {0,...,10}; other
fields (priority, requested resources, machine ID,
missing_type) are optional, with presence rates
reported. `missing_type` if present must be in
{0,...,5}; `missing_type=0` means no declared
missing-event repair; nonzero means source
reports reconstruction/missingness, not an exact
independently observed transition.

For BOTH tables, report counts of whole prefix
lines parsed (0..500), keyed event types,
timestamp minimum/maximum, adjacent timestamp
inversions within the prefix, missing-key counts,
reported missing-type flags and object provenance
only. Do not infer population proportions,
true queue-wait durations, event availability
latency, or total trace-wide missingness.
Never assume file shard order equals event-time
order: inversions are descriptive, not automatic
source rejection.

An entirely independent synthetic causal gate
tests strict `event_time < prediction_origin`;
a placement event is not guaranteed actual
process start; nonzero missing flag is excluded
from exact-event reconstructive claims. The
instantaneous state at origin must not use an
event with equal or later timestamp.
Similarly, a fully aggregated usage sample
`[start,end)` cannot be released as a prior
feature until `end < origin`. This D02
does **NOT** download `instance_usage`, so
there is no empirical measurement of window
missingness or actual resource occupation.

redirect, requester-pays, nonmatching prefix, bad
generation/metadata, or unavailable source. No
alternate source.

`SOURCE_PREFIX_FORMAT_REJECTED`: bytes retrieved but

`SOURCE_PREFIX_AUDITED`: BOTH official selected objects
authenticated by GCS name + generation, both bounded
prefixes yield >=1 valid complete JSON event line,
both independent checks agree and synthetic
causal boundary tests pass. This is only a
NONREPRESENTATIVE PREFIX audit, and NOT a
validated event-stream reconstruction or
independent predictive improvement.

ALL outcomes, including access blocked/negative,
must be persisted in immutable first-run report
metadata with source metadata generation, requested
byte ranges and SHA-256 of bytes actually consumed
when available; archive by GitHub Actions after
reviewed merge, never replace the first archive.
Do not treat first-run CI job success as
`SOURCE_PREFIX_AUDITED` without inspecting
its actual report.
