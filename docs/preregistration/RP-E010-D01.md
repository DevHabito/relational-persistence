# RP-E010-D01 — Frozen third-party production workload source audit

**Registration before any RP-E010 source download, source-byte inspection
or predictive scoring.** This is a **data-eligibility checkpoint**,
not a test of the relational persistence hypothesis. In particular,
NO RP-E010 predictive result will be computed from this record.

## Motivation and no-fabrication boundary

Earlier RP-E007/009 forecast successes were created by our
own executable queue implementations. RP-E008 was strictly
in silico. RP-E010 must work with a trace collected by third
parties in an operational production system rather than
relabeling simulation or our own service instrumentation.

Do **NOT** use the NASA-iPSC-1993 SWF as a source of original
submission/queuing times: the dataset's own conversion notes
explain that actual arrival/submission times are absent and
the converter substituted start times. Its numeric SWF
"submit" field cannot prove a measured arrival time.

Instead, audit HPC2N Seth, a Swedish university-operated
production Linux cluster historically scheduled with Maui,
as described by the Parallel Workloads Archive (PWA).
The trace has third-party submit, wait and runtime
fields. The archive's **cleaned** version removes dominant
user activity and anomalous bursts, which must be
acknowledged and must not be described as untouched
natural sampling.

**Authoritative source descriptions:**

- https://www.cs.huji.ac.il/labs/parallel/workload/l_hpc2n/
- https://www.cs.huji.ac.il/labs/parallel/workload/swf.html
- https://doi.org/10.1016/j.jpdc.2014.06.013

## Registered SWF audit, no modeling

SWF v2.2 has exactly 18 whitespace fields per job
record, with header lines starting `;` as comments.
Fields 1–5: job ID, submit time, wait time, runtime,
allocated processors. Fields 11 and 15 are status and
queue ID. Missing values may be encoded as -1.

The D01 checker must count **all data lines** with
exactly 18 fields, detect whether numeric values parse,
require unique positive job IDs, and report without
erasure or substitution:

- number of parsed lines and wrong-width lines;
- total lines with missing/negative submit, wait,
  runtime or processor values;
- rows with nonnegative submit/wait/runtime, positive
  processors and `status==1`;
- order of submit times (nondecreasing) and repeats;
- header/comment line count, source byte count,
  source Git blob SHA-1, SHA-256, and the number
  of missing status/queue metadata values;
- count of job IDs appearing more than once.

No distribution of outcome labels, holdout prediction,
loss, model coefficient, candidate capacity B,
recovery time or selected test window is to be
calculated in this checkpoint. Do not preview whether
the trend model would win.

## Frozen D01 decision

- `DATASET_SCHEMA_VERIFIED` only if exact pinned byte
  identity matches; there are no invalid-width
  noncomment lines or unparseable numeric identifiers;
  all job IDs are positive and unique; observed
  nondecreasing submit times are valid for records
  with nonnegative submit; and the raw corpus
  includes at least 1,000 individually eligible
  completed rows with valid submit, wait, runtime
  and processors.
- `DATASET_SCHEMA_REJECTED` if the pinned source
  is readable but violates a structural gate
  including the identity conditions above. Record
  the precise violations without changing thresholds.
- `SOURCE_ACCESS_BLOCKED` if the exact pinned file
  cannot be fetched or GitHub authentication/network
  access prevents observing source bytes. No
  inference from an inaccessible mirror.

The D01 code must include adversarial fixtures for
bad Git SHA, duplicate IDs, wrong-width rows,
negative/missing times, out-of-order submit, and
invalid bytes; an independently implemented
second parser must agree on eligibility/structural
counts for fixture and first real source. A single
original GitHub Actions execution should archive the
result JSON and (if authorized) the original retrieved
bytes as a temporary artifact, while a permanent
replay record must retain source SHA256 and run URL.
Do not create a new experiment by automatically
rerunning the first attempt after failure.

**No outcome claim:** even a passing D01 proves only
that externally recorded SWF columns are usable for
further investigation. There remains substantial
confounding from parallel processors, queue policies,
cleaning, censoring and unavailable machine-level
scheduling states. A separate E010 observational
prediction protocol is required before defining
training/holdout boundaries, observational outcomes,
baseline models and hypotheses.

## Source credit and limitations

The original HPC2N workload was provided by HPC2N
and credited by its archive to **Ake Sandgren**,
with the mirror merely a distribution channel.
The PWA source notes anomalous and repaired
records, as well as 324,500 removed records in
the cleaned dataset. The dataset is not a
simple homogeneous single-worker FCFS queue.
The scientific scope is workload trace
**feasibility**, not a proof in Lean 4,
an independent real-time sensor or evidence
for `C=B/(I*tau)`.
