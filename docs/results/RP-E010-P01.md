# RP-E010-P01 — First external historical HPC wait-time forecast

**Original registered decision: `NO_REGISTERED_OBSERVATIONAL_GAIN`.**

The predeclared two-sample **archive-derived aggregate
waiting-job trend** did **not** improve real
third-party historical HPC task waiting-time
forecasts compared with **either** of its two
primary classical controls. The source and
prediction audit was valid: this is a
**registered negative predictive result**, not
a source or instrumentation failure.

## Fixed target and input construction

The observational target for each
eligible job j is **submission-to-start
waiting time**, `Y_j=wait_j`, measured in
seconds. This is **not** the system
post-perturbation recovery endpoint
measured in RP-E007 or RP-E009.

At job submission `t`, two archived
aggregate waiting counts were
reconstructed only from already
recorded arrival/start events:

```text
q(u) = number of records with submit < u <= submit + wait
q_prev = q(t - 120 s)
q_last = q(t - 60 s)

started W_t = jobs whose original start satisfies
              t - 3600 <= start < t - 60
B_t = count(W_t) / 3540 seconds
H_t = mean(wait for jobs in W_t)

STATIC  = q_last / B_t
TREND   = max(0, 2*q_last - q_prev) / B_t
HISTORY = H_t
```

The fourth, secondary comparator was
the **diagnostic-block mean waiting
time**, calculated before held-out
evaluation. No candidate predictor
has a fitted coefficient, and all
feature clocks precede each job's
submission. The reconstructed queue
count is an **archive-derived
global proxy** of a multi-resource
Maui-scheduled cluster; it is not
a direct, queue-specific FIFO sensor.

The two algorithmic oracles — sorted
arrival/start binary search and a
chronological event sweep — agreed
at all requested feature snapshots.
A source-only eligibility filter
precedes the computation; source
records with unknown completion,
wait or processors were treated
exactly as preregistered. **No
long waits were truncated**, no
zero waits removed and no held-out
job or subgroup was excluded for
prediction accuracy.

## Primary result — forecast accuracy

All values below are **unweighted
mean absolute errors (MAE) in seconds**,
rounded for readability. The original
JSON retains full decimal output.

| Frozen predictor | Held-out MAE (s) | MAE (hours) | Role |
|---|---:|---:|---|
| Diagnostic-only mean | **83,834.22** | 23.29 | Secondary, simple control |
| Historical started-job mean | **123,965.25** | 34.43 | **Primary classical comparator** |
| Static aggregate backlog / start rate | 227,534.07 | 63.20 | **Primary classical comparator** |
| Two-sample queue trend / start rate | **234,691.80** | **65.19** | **Registered candidate; failed** |

The TREND model had **3.15% greater**
MAE than STATIC, and **89.32% greater**
MAE than HISTORY, rather than being
10% better than **both**. The
diagnostic-only constant also had
substantially smaller error than
TREND. The original binary decision
is therefore
`NO_REGISTERED_OBSERVATIONAL_GAIN`.

The large absolute values reflect
very long waiting-time errors in
this HPC trace; they are NOT
milliseconds. We did not change
the units, substitute median error,
trim outliers or choose favorable
times after seeing the result.

## Scientific interpretation and next step

**This observation contradicts
the claim that the unfitted
two-sample trend universally
improves waiting-time forecasts.**
The trend passed restricted
software recovery tests in
RP-E007/009 and a model stress
test in RP-E008, but it failed
on a different **observational
endpoint** — historical task
submission-to-start waiting
under parallel scheduling.
That is evidence of limited
transfer, not direct refutation
of the earlier, narrower
software recovery results.

It would be inappropriate to
post-hoc redefine queue capacity,
use future start information,
remove the largest waits,
change the two snapshots,
add fit coefficients or shift
the 70% boundary and call the
same held-out results a new
preregistered success.

A better future scientific
question is whether a
**scheduler-appropriate** model
using resource requests,
queue/partition policy (if
independently observable) and
older completed events predicts
future waits beyond strong
classical controls. That
requires **a different
registered design and new
untouched evaluation data**.
These 49,995 held-out labels
are now historical development
evidence, never again a
blind test set.

No new Lean theorem was proposed;
passing Lean regression certifies
separate mathematical source,
not the empirical validity of
a relational persistence law
or the scalar `C=B/(I*tau)`.
