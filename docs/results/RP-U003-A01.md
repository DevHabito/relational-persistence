## Exact registered ensemble and interventions

**N=684** labeled connected six-node, exactly
seven-edge undirected graphs with protected
source node 0 / target node 5, no direct terminal
edge (0,5), degree 2 at BOTH terminals.
This finite family is fully enumerated;
it is NOT a representative sample of
ecological/healthcare/industrial networks.
Repeated isomorphic graphs with different
labels are part of the registered ensemble;
they must not be described as independent
stochastic draws.

For EACH network, EVERY original internal
node 1,2,3,4 is removed in a separate
scenario: **2,736 loss scenarios**, each
with six after-damage snapshots t=1..6.
Total primary exact evaluations: **16,416**
scenario-time observations per policy.
All competing policies receive exactly
the SAME surviving node count and cumulative
number of restored edges at each scenario/tick.
Equal restoration-edge budgets are NOT
equal computational/information budgets.

Four fixed policies:
`ASC` (neighbor ID order), `DEGREE`
(original degree descending), `GREEDY1`
(immediate best (F1,F2)), and `LOOKAHEAD2`
(best one more simulated choice using the
known blueprint, with registered tie rules).

Task-specific F1 = reachability from
source 0 to target 5 by any path.
Stronger F2 = presence of TWO internally
vertex-disjoint source-to-target routes.
These are classical graph-theory functions,
not calibrated ecological or clinical outputs.

## First original complete source outcome

| Equal-edge-budget repair policy | Exact F1 successful case-ticks / 16,416 | Exact F2 successful case-ticks / 16,416 |
|---|---:|---:|
| ASC | **15,736** | **6,980** |
| DEGREE | **15,748** | **7,092** |
| GREEDY1 | **15,888** | **7,852** |
| LOOKAHEAD2 | **15,888** | **7,968** |

**Preregistered primary H1 was supported**:
LOOKAHEAD2 F1 count strictly exceeds
BOTH ASC and DEGREE by **152** and
**140** successful case-ticks, respectively.

**Critical negative/limitation:** GREEDY1
achieved EXACTLY the same *aggregate F1*
as LOOKAHEAD2 (15,888). The first verdict
does NOT mean lookahead is superior
to greedily selecting the next neighbor.
The LOOKAHEAD2 increase in F2 over
GREEDY1 is **116** case-ticks (7,968
versus 7,852), which is SECONDARY and
task-specific; it does not establish
universal superiority.

This also cannot be interpreted as a
12.5%-like reliability result or as
a statistical effect size over random
future networks: every count is an exact
finite tally from intentionally constrained
artificial topologies.

## What was checked versus what is not yet certified

The registered first-original process
reported no errors. The implementation
includes a distinct graph enumerator
using combinations and a second one
using integer edge masks; source-family
matching and exact first-family
hash were checked. Per-state BFS and
independent DFS simple-path oracles
checked F1; F2 was independently checked
through vertex-disjoint paths and
single-interior-vertex cut tests.
The protocol additionally requires
comparison with offline function-specific
repair envelopes and case-level
negative examples. The archived case-level
report is the source of truth for these
more granular quantities.

The full original JSON contains far more
data than can be usefully displayed in
a short narrative. This report intentionally
restricts numeric interpretations to
the original first-run console output and
SHA-pinned manifest available through the
original successful GitHub workflow. It
does NOT claim independently revalidated
the detailed win/loss or oracle-regret
counts in this report, nor does it
silently omit adverse cases.

The previous results RP-U001/RP-U002
were known when U003 was designed.
The 684 graphs provide broader
**finite model** coverage, not genuine
out-of-sample evidence from physical
systems or graph distributions.

The lookahead comparator knows the
complete original topology and
the task's terminal reachability
function, whereas ASC and DEGREE
use less information. Even with the
same edge-count cost, the policies'
information and computational
requirements are NOT equalized.
The observed advantage can be
attributable to standard path-aware
repair, without introducing a new
relational-persistence mechanism.

**Prior art:** graph vertex connectivity
(Menger), constrained graph restoration,
network resilience, and
optimization of pairwise connectivity
are established. In particular:
Hu et al. (2016),
[*Recovery of infrastructure networks
after localised attacks*](https://doi.org/10.1038/srep24522);
Averbakh and Pereira (2018),
[*Lateness Minimization in Pairwise
Connectivity Restoration Problems*](https://doi.org/10.1287/ijoc.2017.0796);
and Gao, Barzel and Barabási (2016),
[*Universal resilience patterns in
complex networks*](https://doi.org/10.1038/nature16948),
with [erratum](https://doi.org/10.1038/nature18019).

## Honest next gate

The next separately preregistered
experiment should use either:
(a) a **real** network restoration
log with heldout dates and information
availability verified at each decision,
or (b) a distinct graph family with
**degree-sequence matching and
genuinely equal information or
measured CPU budget** for comparators.
Test strong classical path-aware controls
and report all losses, not just
the two simple baseline advantages.

No theorem can be claimed here about
arbitrary dynamic graph repair.
Do not reinterpret the old external
RP-E010/E011 negative forecasts
or validate `C=B/(I*tau)` by analogy.
