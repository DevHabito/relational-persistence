# RP-E007-P01 — Frozen prospective temporal-backlog forecast comparison

**Registered before any RP-E007 implementation or new measurements.**
The design was motivated by the negative RP-E006 outcome and existing
queue estimation methods. It is therefore **not** a blind discovery
independent of the E006 research history. The first RP-E007 holdout
must be newly collected; historical RP-E006 holdout records are not
admissible test cases or model-tuning observations.

## Question and prior-art boundary

When forecasting post-injection queue recovery in the *same* deliberately
simple hosted FIFO software system, does the **latest observed short-term
backlog slope**, used to extrapolate the backlog to the forecast origin,
improve holdout MAE at least 10% over a static queue snapshot?

This is **classical time-dependent queue estimation** (see Ross, Taimre
and Pollett, Queueing Systems 55, 131–138, 2007,
https://doi.org/10.1007/s11134-006-9009-2); the comparison is not a new
theorem, a novel physical law or validation of B/(I*tau).

## Frozen observations and partition

Reuse, **unchanged**, the RP-E006 source instrumentation defined in
\`experiments/rp_e006_acquire.py\`, with the same three accepted-load
targets N={60,100,140}, configured action lags d={15,70,120} ms, nominal
3-ms task submissions, calibrated pretrial B, single-worker FIFO
processing 12 ms before action and 6 ms afterwards, 25-ms health
sampling and independent sampled-idle endpoint Y after injector end
with 500-ms confirmation. Exact source of Y is injector end and
replayed \`monitor-samples.jsonl\`, not a candidate predictor.

Use TWO NEW sequential GitHub-hosted Ubuntu 24.04 VM jobs in a single
new workflow ID and source SHA:

1. **Train/diagnostic block:** 18 new interventions, two of each of
   the nine registered cells, using existing frozen train seed
   \`20261026\`. No new fitting or tuning based on these observations.
2. **Future held-out block:** 9 additional fresh service interventions,
   one per cell, using the existing frozen test seed \`20261027\`,
   on a new subsequent VM job. All original source logs retained.
3. The two sets are not independent natural-world samples, and have
   shared code/cloud provider. They are a restricted software
   measurement benchmark only.

A model-independent replayer must recover every sample and confirm
the original E006 run-quality gate for all 27 new trials. Any failed,
censored, missing, overwritten, malformed, duplicate or misassigned
observation makes the entire RP-E007 result
\`STOP_INSTRUMENTATION\`. No replacing failed experiments by rerunning
them under the original experiment ID.

## Frozen forecast origin, admissible features and models

Forecast origin = **actual injector end**. Using only raw timestamped
monitor observations at or before that origin, choose the last
two records in chronological order, \`prev\` and \`last\`.
Let \`q=queued+active\`; define
\`delta_t=(last.observed_ns-prev.observed_ns)/1e9\`,
\`remaining_t=(end_ns-last.observed_ns)/1e9\`, and
\`slope=(q_last-q_prev)/delta_t\`.

For both methods, \`B>0\` is the same pretrial saturated calibration
rate (work units per second) from the P02 calibration oracle.
Both use the already declared postaction throughput multiplier 2.

- Primary **static baseline**, **unfitted**:
  \`Yhat_static=max(0,q_last/(2*B))\`.
- Primary **two-sample trend extrapolation**, **unfitted**:
  \`q_at_end_est=max(0,q_last+slope*remaining_t)\`
  and \`Yhat_trend=max(0,q_at_end_est/(2*B))\`.
- Secondary **training-average constant** computed only using the 18
  new training Y values: no training labels from RP-E006.
- No grid search, smoothing-window change, regression, shrinkage,
  alternate slope statistic, additional feature, after-the-fact
  adjustment or selection. This trend extrapolation is fixed
  algebra, not a fitted novel relational-persistence predictor.

**Required data gates:** exactly two genuine distinct original monitor
records before or at end; \`prev.observed_ns<last.observed_ns<=end_ns\`;
\`0<=end_ns-last.observed_ns<=150,000,000\`;
\`0<last.observed_ns-prev.observed_ns<=150,000,000\`;
all \`observed_ns\`, \`queued\`, \`active\`, \`completed\` and service
timestamps valid nonnegative integers; B finite positive; every
frozen recorded feature hash matches the original log, and
each trial's original \`Y\` is independently replayed without using
the feature calculation.

**No post-end monitor sample**, Y or future service state may influence
either estimate. The monitor trace is already archived by acquisition;
the RP-E007 auditor must not rewrite it. Both predictions must be
reproducible from the archived source bytes alone.

## Primary success/failure criterion (one-time holdout)

On the **nine newly observed held-out trials**, compute arithmetic
mean absolute error in seconds for the two frozen estimates.

- \`PASS_TREND_INCREMENT\` iff \`MAE_static>0\`,
  \`MAE_trend<=0.90*MAE_static\`, and all instrumentation and
  contamination checks pass.
- \`NO_REGISTERED_TREND_GAIN\` otherwise if all measurements
  are valid, including zero-static-MAE.
- \`STOP_INSTRUMENTATION\` for failed source, provenance,
  missing/tampered events, timestamp ordering, inaccessible
  pre-end samples, replay disagreement, nonfinite estimates,
  or fewer than 18 and 9 valid trials.

Freeze those three outcomes before first measurement. The use of a
single held-out 9-trial set means no population confidence interval
or cross-domain generality is established. Record every individual
Y, q_prev, q_last, two timestamps, slope, predictions and errors,
secondary train-average MAE, original source hashes, trial IDs,
both job statuses and the precise first-run verdict.

## What an outcome can and cannot say

A PASS would show local time-aware backlog forecasting is useful
relative to a static queue snapshot **for this instrumented
software scenario**, a well-established possible phenomenon.
A NO_GAIN would show that the stated frozen extrapolation fails its
threshold in this particular setting. Neither supports or refutes
a general physical law. No new Lean theorem is proposed; pinned
Lean CI is a regression requirement only.

This study does **not** test whether a vector called "relational
persistence" is physically valid. If future mathematical or physical
claim-building uses the measured slope, it must cite this established
queueing precursor and register a new independent test.
